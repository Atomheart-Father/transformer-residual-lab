# R5-W / 云就绪矩阵：云端能回答什么、不能回答什么

**一句话：云端 CUDA 只能做"格式与质量"的早期验证（这是编码的属性，与硬件无关）；任何云端速度数字都不能迁移到 M4 Metal。0.6B 在云端没有意义。**

- 纯设计与算术。**未租用、未登录、未下载、未安装任何东西。**
- 与 `2026-10-r5-errata.md` §3 配套：本地缺 Metal 编译器，但 **imatrix 与 quantize 是 CPU 路径**，质量验证可以本地做；云端补的是"更大模型上的格式有效性"。
- **本轮不装 Xcode**（7 GB），已按审查要求承诺。

---

## 1. 边界：三类结论，只有一类可迁移

| 结论类型 | 例子 | 云端 CUDA 能否产出 | 能否迁移到 M4 |
|---|---|---|---|
| **格式有效性** | IQ2_XS 能否在正确 imatrix 流程下编码成功、字节数、张量类型组合 | 能 | **能**（编码是权重属性，与硬件无关） |
| **编码质量** | 同 checkpoint 下 Q2/Q4/BF16 的 NLL 差、KL、top-1 | 能 | **能，但只到"信息损失"层面**：累加精度不同会让 NLL 有微小差异，不是逐位一致 |
| **执行速度** | tok/s、GB/s、兑现率 R | 能，但那是 **CUDA** 的数 | **不能** |

第三条是硬边界。CUDA 与 Metal 在三个维度上都不同：

| 维度 | CUDA（T4/A100） | M4 Pro Metal |
|---|---|---|
| 带宽 | T4 320 GB/s；A100 40GB 1,555 GB/s | 273 GB/s（规格峰值） |
| 低位 kernel | `ggml-cuda/mmq.cu` 系列，dp4a / mma | `mul_mv.metal` 的 simdgroup 归约 |
| ALU 预算 | 远高（尤其 A100） | 低，2 bpw 会被 ALU 卡住（R2 §3.1 的条件表） |

**同一个 IQ2_XS 在 A100 上的兑现率可能接近 1.8×，在 M4 上可能只有 0.5×。** 两个数都真实，但不能互相引用。

## 2. 尺寸算术（可复核）

`权重字节 = 参数量 × bpw / 8`

| 模型 | BF16 (16 bpw) | Q4 4.25 bpw | Q2 2.3125 bpw |
|---|---|---|---|
| 0.6B | 1.2 GB | 0.32 GB | 0.17 GB |
| 8B | **16.0 GB** | **4.25 GB** | **2.31 GB** |
| 27B | **54.0 GB** | **14.34 GB** | **7.81 GB** |
| 32B | 64.0 GB | 17.0 GB | 9.25 GB |
| 70B | 140 GB | 37.2 GB | 20.2 GB |

KV cache（示例参数，非特定模型）：

```
KV/token = 2 × L × H_kv × d_head × bytes
8B  示例 L=32, H_kv=8, d=128, bf16 → 128 KiB/token → 8k = 1.0 GiB
27B 示例 L=64, H_kv=8, d=128, bf16 → 256 KiB/token → 8k = 2.0 GiB
```

**这两个 L/H_kv/d 是假设值**，用于给出量级。真实模型要按 `config.json` 重算。8k 上下文之外的 KV 增长是线性的，32k 时 27B 要 8 GiB。

运行时开销：CUDA context + 驱动 + 临时 buffer，按 **1.0 GB** 计（T4 偏紧，A100 宽松）。

---

## 3. 显存适配矩阵

判定式：`权重 + KV(8k) + 1.0 GB ≤ 可用显存`，可用显存按 `卡容量 − 1 GB` 计。

| 卡 | 可用 | 8B BF16 | 8B Q4 | 8B Q2 | 27B BF16 | 27B Q4 | 27B Q2 |
|---|---|---|---|---|---|---|---|
| **T4 16 GB** | ~15.0 | **✗ 18.0** | ✓ 6.3 | ✓ 4.3 | ✗ 57.0 | **✗ 17.3** | ✓ 10.8 |
| **A100 40 GB** | ~39.0 | ✓ 18.0 | ✓ 6.3 | ✓ 4.3 | ✗ 57.0 | ✓ 17.3 | ✓ 10.8 |
| **A100 80 GB** | ~79.0 | ✓ 18.0 | ✓ 6.3 | ✓ 4.3 | ✓ 57.0 | ✓ 17.3 | ✓ 10.8 |

三个要点：

1. **T4 装不下 8B BF16**（16.0 GB 权重 + KV + 开销 = 18.0 GB > 15.0）。审查的原话"不适合无 offload 的 8B BF16"成立，且不是"紧张"，是**差 3 GB**。
2. **T4 装得下 27B Q2**（10.8 GB）。这一格值得注意：**27B@Q2 vs 8B@Q4 是"小模型高精度 vs 大模型低精度"的经典对撞**，而 T4 恰好能同时装下两者。这是免费额度能做的、信息量最大的一个比较。
3. **A100 40 GB 装不下 27B BF16**（57.0 GB）。要做 BF16 锚点必须 80 GB。审查写"A100 40/80GB 的 27B Q4/BF16"，需要拆开：**40 GB 只能做 27B Q4/Q2，80 GB 才能做 27B BF16**。

## 4. 能回答 / 不能回答

| 问题 | T4 16 GB | A100 40 GB | A100 80 GB |
|---|---|---|---|
| IQ2_XS 编码流程在 8B 上是否成立 | ✓ | ✓ | ✓ |
| 8B 上 Q2/Q4/BF16 的 NLL 三方对比 | **✗（无 BF16 锚点）** | ✓ | ✓ |
| 27B 上 Q2/Q4 对比 | ✓ | ✓ | ✓ |
| 27B 上 Q2/Q4/**BF16** 三方对比 | ✗ | **✗（显存不足）** | ✓ |
| 27B@Q2 vs 8B@Q4 的质量对撞 | ✓ | ✓ | ✓ |
| imatrix 对 IQ2_XS 的实际增益 | ✓ | ✓ | ✓ |
| **M4 Metal 上的兑现率 R** | **✗** | **✗** | **✗** |
| **M4 上 2.3 bpw 是否划算** | **✗** | **✗** | **✗** |

**最后两行是这张表的目的。** 云端能把"格式能不能用、质量掉多少"这个问题关掉；"在 M4 上值不值"这个问题，只有 M4 能答。

## 5. 下载量与磁盘

| 产物 | 体积 | 备注 |
|---|---|---|
| 8B BF16 safetensors | ~16.4 GB | 要自己做 imatrix 就必须下 |
| 8B f16/bf16 GGUF（量化输入） | ~16.4 GB | 与上面二选一，GGUF 更省事 |
| 8B Q4 GGUF（现成） | ~4.9 GB | HF 上有预量化 |
| 8B Q2 GGUF（现成） | ~2.7 GB | 但**别人做的 imatrix 流程未知**，可能不是公平基线 |
| 27B BF16 | ~54 GB | Kaggle 磁盘大概率放不下 |
| 27B Q4 GGUF | ~15.5 GB | — |
| 27B Q2 GGUF | ~8.5 GB | — |
| wikitext-2-raw 校准语料 | ~12 MB | imatrix 用 |

**关键判断：要"公平的 IQ2_XS"，必须自己算 imatrix，也就必须下 16.4 GB 的 f16/bf16 源。** 用别人的预量化 Q2 只能做"存在性验证"，不能做公平对比——因为你不知道对方用了什么 imatrix、什么校准集、是否混了更高精度的层。

**磁盘约束**：27B BF16（54 GB）+ 中间产物，在 Kaggle 上基本不可行；A100 实例一般有更大磁盘，但仍需确认。这一项标**低确定性**，必须在租用前查平台页面。

## 6. 额度、费用、不确定性

**这一节的所有数字都标为 E3-未核实，必须以平台当前页面为准。** 我不为过期的额度数字背书。

| 平台 | 常见配置 | 额度（量级） | 费用（量级） | 确定性 |
|---|---|---|---|---|
| Kaggle | T4 ×1 或 ×2（16 GB each）、P100 | 每周数十小时 GPU；单会话有时长上限 | 免费 | **低**：额度与卡型常变 |
| Colab 免费 | T4 16 GB | 每日/每会话浮动，常被抢占 | 免费 | **低**：浮动大 |
| Colab 付费 | T4 / L4 / A100 40 GB | 按订阅档位 | 月费制 | **低**：档位与价格常变 |
| 按小时租用（Lambda / RunPod 类） | A100 40/80、L40S | 按秒计费 | 每小时数美元量级 | **中**：价格波动 |

**三条不确定性必须写进任何云端计划**：

1. **可用性不确定**：免费额度可能排队或抢占，长任务会被中断。对策：把流程切成"可断点续跑"的步骤（imatrix 支持 `--output-frequency` 定期落盘）。
2. **磁盘不确定**：54 GB 级下载在免费档大概率失败。
3. **计费不确定**：按小时租用的实例，**忘记关机是主要成本风险**。

## 7. 最小可行云端计划（三档，按信息量排序）

### 档 1：T4 免费档，只做"存在性 + 对撞"（推荐先做）

```
目标：验证 IQ2_XS 在 8B 上能编出来；做 27B@Q2 vs 8B@Q4 的质量对撞
输入：8B Q4 GGUF (4.9 GB) + 27B Q2 GGUF (8.5 GB) + 8B f16 GGUF (16.4 GB, 算 imatrix 用)
产出：字节数、per-tensor 类型组合、wikitext NLL、KL
限制：无 8B BF16 锚点（装不下）→ 8B 的结论只能标"仅相对 Q4"
```

### 档 2：A100 40 GB，补 8B 三方参照

```
目标：8B 上 BF16 / Q4 / Q2 三方配对，算 D4、D2、ρ
输入：8B BF16 GGUF (16.4 GB) + 两个量化产物
产出：可迁移的质量结论（含 ρ 与 CI）
限制：27B 仍无 BF16 锚点
```

### 档 3：A100 80 GB，补 27B 三方参照

```
目标：27B 上三方配对
输入：27B BF16 (54 GB) + Q4 (15.5) + Q2 (8.5)
产出：跨规模的质量结论（0.6B → 27B 的损伤-规模关系）
限制：成本最高；54 GB 下载是主要时间开销
```

**档 1 与档 2 之间的信息增量最大**：档 1 只能告诉你"Q2 比 Q4 差多少"，档 2 才能告诉你"两者离原模型有多远"。这正是审查 P0 的核心。

---

## 8. 明确不做

| 不做 | 理由 |
|---|---|
| **装 Xcode（7 GB）** | 审查明确要求不为本轮审查安装。本地 Metal 编译继续挂起。 |
| **在云端测速度并外推 M4** | CUDA 与 Metal 的带宽、kernel、ALU 预算都不同，任何外推都是伪造。 |
| **用 0.6B 上云** | 0.6B 太小，缓存效应主导，且云端无 Metal；它的问题本地就能问。 |
| **用别人的预量化 Q2 做公平对比** | imatrix 与校准集未知，无法保证两边对等。 |
| **租用任何实例** | 本轮未授权，且涉及费用。 |

---

## 9. 一句话给决策者

**云端能买到的只有"质量"和"格式有效性"，买不到"在 M4 上快不快"。** 前者是 0.6B 本地也能做的（除 BF16 锚点外），后者只有 M4 能答。所以云端投入的唯一不可替代价值，是**在 8B/27B 这种真实规模上给出带 BF16 锚点的质量结论**——而这恰好也是审查 P0 要求的那个参照。
