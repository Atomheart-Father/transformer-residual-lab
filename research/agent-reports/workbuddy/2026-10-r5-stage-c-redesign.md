# R5-W / Stage C 重设计：三方参照、相对误差预算、以及每层能/不能决定什么

**一句话：把"BF16 只做 L0 真值"改成"BF16 是质量阶梯的锚点"，把"L0 显著更差就停"改成"只有方向塌陷才否决"，把决策量从绝对 ΔNLL 换成无量纲比值 ρ = ΔNLL(Q2,Q4) / ΔNLL(Q4,BF16)。**

- 这是 `2026-10-r4-experiment-readiness.md §4` 的替代版本。R4 原件保留。
- 纯设计。**未执行任何一步。**
- 勘误依据见 `2026-10-r5-errata.md` E-R5-1 与 E-R5-4。

---

## 1. 为什么要改

R4 的 Stage C 有两个结构性缺陷：

| 缺陷 | 后果 |
|---|---|
| BF16 只当 L0 的数值真值，不当质量参照 | 无法排除"Q2 和 Q4 都严重损伤原模型"。Q2 比 Q4 好 0.05 nats，可能只是"两个都坏了，坏得少一点" |
| L0 以"比 Q4 差"作为否决条件 | 2-bit 的重构误差必然大于 4-bit，这条否决恒真，等于禁止研究 2-bit |

两条都指向同一个错误：**把"相对比较"当成了"绝对有效性"**。

## 2. 三方参照的完整定义

### 2.1 三个模型，一批窗口

| 角色 | 具体对象 | 字节（0.6B） | 回答什么 |
|---|---|---|---|
| **锚点** | 同 checkpoint BF16（`mlx-community/Qwen3-0.6B-Base-bf16`，rev `e8e73ff3…`） | 1.2 GB | 原模型的能力水平 |
| **标尺** | 同 checkpoint 的成熟 4-bit（MLX affine 4b g64；Stage B 就绪后换 IQ4_XS） | 319 MB | "可接受的损伤"有多大 |
| **候选** | 同 checkpoint 的 2-bit（MLX affine 2b g64；Stage B 就绪后换 IQ2_XS） | 173 MB | 被测对象 |

**同窗口、同 token 数、同 batch、贪心或同一 seed。** 三者必须共享完全相同的输入张量（落盘 `.npy`，两侧读同一份），不接受"各自取数据但 seed 相同"。

### 2.2 三个差值，一个决策量

```
d4_i = NLL_Q4(window_i)  − NLL_BF16(window_i)
d2_i = NLL_Q2(window_i)  − NLL_BF16(window_i)
Δ_i  = d2_i − d4_i       = NLL_Q2(window_i) − NLL_Q4(window_i)     （逐窗恒等）

D4 = mean(d4)      D2 = mean(d2)      Δ = mean(Δ) = D2 − D4
ρ  = Δ / D4
```

**三条都报，但决策量是 ρ。** 因为：
- `D2` 单独看无法解释——不知道多大的 ΔNLL 才算"损伤"；
- `D4` 提供量纲：它就是这个模型在"成熟低位宽"下已经付出的代价；
- `ρ` 回答唯一有意义的问题：**Q2 的额外代价，相对于 Q4 已经付出的代价，是几倍。**

### 2.3 前置健全性检查（在算 ρ 之前）

```
若 D4 > 1.0 nats：
    Q4 在 0.6B 上已经越界，整条阶梯在标尺处就断了。
    → 报告写"Q4 已越界，Q2 比较无意义"，不得计算 ρ，不得下任何 Q2 结论。
若 D4 的 95% CI 跨 0：
    4-bit 与 BF16 无显著差异，ρ 的分母是噪声。
    → 报告写"该规模下 4-bit 无可测损伤，ρ 不可用"，改用绝对 ΔNLL。
```

这两条必须先跑，因为**它们是 ρ 有意义的前提**，不是可选诊断。

## 3. 判据：ρ 的置信区间，不是点估计

| ρ 的 95% CI | 判定 | 允许写的结论 |
|---|---|---|
| **上界 < 1** | Q2 的额外损伤不超过 Q4 相对 BF16 的损伤 | "在本规模、本语料上，Q2 的额外损伤小于成熟 4-bit 已经付出的损伤" |
| **下界 > 3** | 明确越界 | "Q2 的额外损伤超过 Q4 的 3 倍，在本规模不可接受" |
| 下界 < 1 < 上界，或落在 1–3 之间 | **未测出结论** | "CI 覆盖 [a, b]，无法判定"。**禁止**写成"两者相当"或"Q2 可接受" |

**1 与 3 是人为选定并预注册的倍数，不是从理论推出的。** 报告里必须原样写明这一点。选 1 的理由是"不超过标尺本身的代价"；选 3 的理由是"三倍标尺代价已经无法用'省一半字节'来辩护"。这是工程判断，不是定理。

### 3.1 一个必须写死的逻辑

**CI 跨 1 不等于等价。** 样本不足时 CI 会变宽，宽到跨 1 很容易。把"没测出差异"写成"没有差异"是本项目已经踩过的坑（R2：`<0.01–0.02 nats` 的改善不可选型）。此处的规则是：

```
CI 跨 1  →  结论只能是"未测出结论"，且必须同时报出 CI 半宽
```

不允许用"未测出"去支持任何一方的立场。

## 4. 样本量：ρ 比 ΔNLL 更吃样本

### 4.1 算术

`Δ_i` 是**差分之差**。设单窗 `d` 的标准差 `σ_d ≈ 0.2 nats`（历史估计），`d2` 与 `d4` 同窗口正相关（ρ_corr ≈ 0.7）：

```
σ_Δ = sqrt(2σ_d²(1 − ρ_corr)) ≈ sqrt(2 × 0.04 × 0.3) ≈ 0.155 nats
n = 64  →  CI 半宽(Δ) = 1.96 × 0.155 / 8 ≈ 0.038 nats
```

`ρ` 的 CI 半宽还要除以 `D4`：

| D4（nats） | ρ 的 CI 半宽（n=64） | 能否支撑 1 vs 3 的判定 |
|---|---|---|
| 0.50 | ≈ 0.076 | **能** |
| 0.30 | ≈ 0.127 | 勉强 |
| 0.10 | ≈ 0.38 | **不能** |
| 0.05 | ≈ 0.76 | 完全不能 |

**所以 ρ 的可用性取决于 D4，而 D4 事先未知。** 设计上必须先报 `D4 ± CI`，再决定 ρ 是否可解释。这是一个**依赖数据的判据**，必须写在预注册里，不能事后调整。

### 4.2 本地硬边界

| 项 | 值 |
|---|---|
| 本地最大窗口数 | 64（任一 split） |
| 每窗 token | 128 |
| 可用评测 token | **8,192** |
| 若要 ρ 的 CI 半宽 ≤ 0.1 且 D4 = 0.3 | 需 n ≈ 104 窗（本地不足 1.6 倍） |

**结论：本地 64 窗在 D4 ≥ 0.3 nats 时够用；D4 更小则需要重抽窗口（下载，未授权）。**

## 5. 三层各自的角色（重写）

```
L0 ──诊断，只在机制性病态时否决──▶ L1 ──能力非劣性，决策层──▶ L2 ──只在 L1 边界时补充
```

### 5.1 L0：诊断，不是关卡

| 指标 | 角色 | 能否否决 | 阈值来源 |
|---|---|---|---|
| 逐输出行 `cos` 的 1 分位 | **方向是否还在** | **能** | 机制性：R2 已证"只修方向回收 79%，只修幅度更差"，方向塌陷即不可救 |
| `rel_rms` 分布 | 幅度误差量级 | **不能** | — |
| 逐元素相对误差 99.9 分位 | 尾部是否爆炸 | 能 | 需预注册 |
| 每行 `max_abs_level` 直方图 / 饱和比例 | 是否大量行被钉在最高 level | 能 | 需预注册 |
| 分组（`q/k/v/o`、`gate/up/down`、`embed/head`、按层） | 归因 | **不能** | — |

**`rel_rms` 比 Q4 大这件事不再是判据。** 它必然更大。它只用来解释 L1 的差异来自哪个 tensor。

方向塌陷的预注册形式（示例，需在跑之前定稿）：

```
若任一关键投影（q/k/v/o 或 gate/up/down）的逐行 cos 1 分位 < 0.5，
则该 tensor 判为方向塌陷 → L0 否决，不再进 L1。
```

`0.5` 这个数取自 R2 的实测背景：串行单元在 rel.err 0.61 时 cos 仍有 0.79，说明 cos 0.79 对应"结构尚在"；0.5 是明显更松的下限，用于捕捉塌陷而非区分优劣。

### 5.2 L1：决策层

| 指标 | 说明 |
|---|---|
| `D4`、`D2`、`Δ`、`ρ` | 四个量全报，配对 bootstrap 10,000 次 |
| KL(BF16 ‖ q) | 中位数与 90 分位；**Q2 与 Q4 并列**，不设绝对阈值 |
| top-1 一致率 | 同上，**不设 90% 阈值** |
| 退化 | `distinct-4`、最长重复子串、连续相同 token 最大游程；三者都在 Q2/Q4 上并列 |

**L1 是唯一有权做"接受/拒绝"决定的一层**，判据是 §3 的 ρ CI。

### 5.3 L2：只在 L1 落在灰区时补充

| 触发条件 | 做什么 |
|---|---|
| ρ 的 CI 上界 < 1（明确可接受） | **不必跑 L2** |
| ρ 的 CI 下界 > 3（明确越界） | **不必跑 L2** |
| ρ 落在灰区 | 跑 L2，看是否有"格式性崩塌"（JSON schema 遵循率、语法可解析率） |

**L2 的判据仍是配对翻转**（同题、贪心、同 max_tokens，McNemar），不是绝对分数。0.6B 在 GSM8K/HumanEval 上接近地板，**绝对分数不构成 27B 的证据**——这一条 R4 已写，保留。

## 6. "仅相对 Q4" 这个标签什么时候用

审查要求：若原 BF16 无法加载，结论必须标成"仅相对 Q4"。

**本项目不触发**：BF16 就在本地（1.2 GB），Stage B 侧也能用 `convert_hf_to_gguf.py --outtype bf16` 产出同精度 GGUF。

但标签规则仍要落成文字，以备将来在别的模型上复用：

```
[绝对]  三档（BF16 / Q4 / Q2）全部跑通  → 可写"相对原模型的损伤"
[相对]  只有 Q4 与 Q2 跑通             → 必须写"仅相对 Q4，未测原模型损伤"
[无效]  BF16 跑通但 Q4 未跑通          → 只能写"Q2 相对原模型的绝对损伤"，无标尺
```

**任何情况下都不允许用 [相对] 的数据去支撑"2-bit 可用"的结论。** 那只能说明"比 4-bit 差多少"，不能说明"还能不能用"。

## 7. 这套设计不能决定什么（写死在报告里）

| 不能决定 | 原因 |
|---|---|
| 27B 上 Q2 是否可用 | 0.6B 与 27B 的损伤-规模关系未知；本项目从未测过跨规模 |
| 任何任务级能力结论 | 0.6B 在地板附近，L2 只能发现崩塌，不能比较能力 |
| `<0.02 nats` 区间的差异 | 本地 64 窗的 CI 半宽 ≈ 0.049 nats，够不到 |
| Metal 上的速度 | Stage C 全程是质量，速度是 Stage A/B 的事，两者不得互相引用 |
| "Q2 与 Q4 等价" | 只有 ρ 的 CI 完全落在 [0.9, 1.1] 且样本量足够时才能说"近似等价"，本设计的样本量达不到这个精度 |
