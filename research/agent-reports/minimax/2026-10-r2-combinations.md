# R2 — 组合兼容性矩阵：**实际已测量的组合** vs **可组合的假设**

**任务**：R2 / Issue #1。研究者：MiniMax。日期：2026-10-21。

**配套文档**：结论见 **`2026-10-r2-report.md`**（主报告），逐条 URL 与证据等级见 **`2026-10-r2-evidence.md`**。本文件只负责**组合维度的判定**，不重复单方法结论。

## 0. 判读规则（沿用 `research/PROTOCOL.md`）

1. **"两个方法都有效" ≠ "组合有效"。** 严格区分三种状态：
   - **✔✔ 已发表的联合测量** —— 同一篇论文或同一系统里，**两个组件同时开启并被一起测量**。
   - **✔ 已实现 / 已声明兼容，但无联合测量** —— 组件被声明可共存，或有工程实现，但**没有把两者放在一起测过**。
   - **△ 仅工程推断** —— 数学上可组合，但有明确冲突或开销抵消。
   - **✘ 互斥 / 不适用** —— 不是"效果差"，是"对象不存在"或"机制直接冲突"。
2. 每格必须写清：**共同假设** / **潜在冲突** / **互相抵消的开销**。
3. 消费级 batch=1 还要过 **§C.2 的约束轴判据**：**字节** > **串行轮次** > **容量** >> **FLOPs**。
4. **无损等级**必须带 L0–L4 标签，不写"无损"。

> **本文件的核心立场**：这一轮最重要的发现不是"哪个组合好"，而是——**文献里"已发表的联合测量"极少，而任务书点名的四组配对里有两组根本不存在联合测量**。下表逐条给出证据。

## 2. 任务书指定的四组配对 —— 逐条判定

### 2.1 `YAQA / CurveTQ × 稀疏权重布局`

| 维度 | 判定 |
|---|---|
| **联合测量是否存在** | **✘ 无。** 本轮系统检索（arXiv API：`abs:(FFN OR feed-forward) AND abs:sparsity AND abs:quantization`、`abs:sparsity AND abs:quantization AND abs:(bandwidth OR "memory traffic")`，2026-10-21）**未找到任何把 YAQA 或 CurveTQ 与稀疏权重布局联合测量的工作**。最接近者全为架构类或需训练：Hardware-Native Joint Sparse-Quantization for Trillion-Scale MoE（`2610.02241`）、SPARQLe（`2606.00365`）、SALCA（`2604.24820`）、Compression Trinity（`2608.24070`）`[P]` 摘要级 |
| **数学兼容** | ✔ 两者作用在不同环节：**自适应舍入 / 曲率加权 = 编码时的舍入决策**；**稀疏布局 = 存储与访存布局**。不矛盾 |
| **信息丢失** | ✔ 无重叠（一个是编码误差，一个是哪些权重存在） |
| **训练要求** | CurveTQ = PTQ（需校准）；**YAQA = PTQ + `O(m²n²)` 级搜索工作量**（FastKron 明确：*"YAQA improves over the sequential depth but still has quartic total cost"*）`[P]` |
| **额外开销** | ⚠ **YAQA 的校准成本在消费级不可接受** —— 再好的 PTQ 算法，若校准本身要 `O(m²n²)` 总工作量，**在 24 GB 设备上根本跑不动校准**。这是一个被严重低估的部署约束 |
| **潜在互斥** | ✘ **如果"稀疏"指非结构化稀疏，则与 trellis/格码的打包布局直接冲突** —— QTEA 自述：*"Many leverage unstructured sparsity to mitigate this loss, but at the cost of **regularity and GPU-friendly execution**."* `[P]` 而 trellis 的 bitshift 码本身就是**规则、位对齐**的打包格式；往里塞非结构化稀疏会同时破坏码的字长规整性与访存局部性 |
| **消费端额外判据** | ⚠ 曲率加权/舍入搜索是**离线**的（PTQ），运行时零开销；**但"稀疏布局"在 Metal 上必须重写**（SpQt 的 zigzag 是 fork-only，~8K 行 C/C++ + Metal Shading Language `[P]`）⇒ **两半的部署成本不对称：容易的一半已经免费，难的一半还没人写** |
| **总判定** | **△ 可组合但互斥冗余，且搜索成本致命。** 优先级低 |

### 2.2 `Prox × 极低位宽`

| 维度 | 判定 |
|---|---|
| **联合测量是否存在** | **⚠ 精度上联合测过，速度上明确没测。** Prox Fig. 6 = AWQ / FP8 / W4A16 / W8A8 × FFN 稀疏度下的 **Qwen3-8B WikiText PPL**（精度）`[P]`。**速度维度的联合测量不存在** —— 论文原话：*"realizing these gains requires specialized kernels that jointly support sparse execution and low-bit arithmetic, which we leave to future work."* `[P §5.1]` |
| **数学兼容** | ✔ Prox Stage 1 **本就使用 INT4 量化代理权重** `[P]` ⇒ 量化和稀疏在 Prox 内部是**耦合设计**而非事后拼装 |
| **信息丢失** | ⚠ 两处独立叠加：代理的**排序误差**（exact-proxy top-k 重叠 **82.04 %** 均值 / 82.77 % 单 token，**且只在 Qwen3-8B 单层 × 512 token 上测**）`[P]` 与**量化误差** |
| **训练要求** | Prox 训练自由 + 需 **20,480 token Alpaca 校准**（逐层顺序校准，10 模型 × 4 稀疏度 = 40 组阈值配置）`[P]` |
| **额外开销** | **+12 % 权重存储**（INT4 代理权重）`[P]` + Stage 1 的 GEMV 成本（α = 1/3，实测 0.234–0.351）+ 代理占 **FFN 时间 19.9 %** `[P]` |
| **潜在互斥（设计层）** | ⚠ **Prox 的 Stage 2 用"原始全精度权重"精确计算** `[P]` ⇒ **它与"极低位宽"在设计上是部分冲突的**：极低位宽追求的就是不用全精度权重。**若权重是 2-bit，Stage 2 的"精确"就没有了。** 论文未讨论 |
| **潜在互斥（带宽层，本报告判定）** | ✘ **Prox 的 up/gate 是"散布输出通道"稀疏，在行主序分组量化布局下 ≈0 % 字节节省** `[推算]`：Qwen3-8B（`d_ff=12288`，`k/N=0.3`）下 `g=256` ⇒ 触及分组数 `48·(1−0.7^256) ≈ 48`；`g=32` ⇒ `384·(1−0.7^32) ≈ 384` ⇒ **每个分组都被触及**。**只有 `W_down` 因行维连续而能省字节。** ⇒ **Prox 的稀疏机制与"极低位宽"在带宽轴上几乎没有交集** |
| **消费端额外判据** | ✘ 24 GB 目标下 **+12 % 常驻代理权重**是直接打击（27B 4-bit ≈ 16 GB，+12 % ≈ 1.9 GB）；且其头条工作点（70 % 有效稀疏）强制 **s₁=70 %**（代理保真度最差处）、**s₂=76.7 %**，并有真实质量损失（Qwen3-8B 76.1→68.6、**Qwen3-4B 71.1→58.7**）`[P]` |
| **总判定** | **△ 精度上联合测过、速度上明确没测；存在设计层与带宽层两处互斥。** 若要组合，必须先解决"Stage 2 在低比特下如何仍保持精确"——**这等于换掉 Prox 的核心机制** |

### 2.3 `等价旋转 × 低位宽`

| 维度 | 判定 |
|---|---|
| **联合测量是否存在** | **✘ 无。** 没有论文把 gauge/旋转变换与 trellis/格码 2-bit 联合测量。**最接近的是 CurveTQ 本身——但它做的是相反的事：去掉旋转。** |
| **数学兼容** | ✔ 旋转与低位宽编码在数学上兼容：旋转使权重近高斯，利于编码 |
| **信息丢失** | ✔ 各自独立（旋转是 L0 精确恒等；量化是 L4） |
| **训练要求** | 旋转可能需学习（SpinQuant）或用随机（QuaRot / QTIP / Proteus） |
| **额外开销** | **旋转必须在每个解码步在线撤销** `[P]`（CurveTQ 原文：*"rotate each weight matrix by a random orthogonal transform, which must be undone at every decoding step"*） |
| **潜在互斥（★ 核心冲突）** | ✘ **不是可乘关系，是替代关系。** 三条独立证据：<br>① **CurveTQ**：*"the rotation removes this within-block variation, so **weighting in the native basis and rotating are substitutes**"* `[P]`<br>② **RoPE-Aligned Q/K Rotations**：**与 RoPE 交换的正交映射恰好只有逐频率对旋转**（*"for distinct frequencies, no other single-head orthogonal map commutes with RoPE"*），而这一族在 W4A4KV4 下**比整头 Hadamard 更差**（四个 checkpoint，短长上下文 PPL 均升）`[P]`<br>③ **OSAQ**：用 **Hessian 零空间的加性变换**达到同样的离群点抑制，且**可离线吸收进权重、零推理开销** `[P]` |
| **补充：旋转与"折叠进相邻层"的矛盾** | ⚠ PeRQ 明确把排列**合并进周围权重张量**以避免推理开销 `[P]`；但**相邻层若也已被量化，合并就会改变它的量化误差** —— **这个矛盾在文献里没有被正面处理** |
| **补充：Functional Equivalence 的定理** | ⚠ **RoPE 显著压缩了注意力的对称群** `[P]` ⇒ **在现代 LLM 上，本来就更少的 gauge 自由度可利用**。任务书预设的"用 gauge 变换找到更易压缩的变换"在当前证据下不成立 |
| **总判定** | **✘ 互斥的替代关系。同时做两个 = 付两次代价买一次收益。** 若要"离群点抑制 + 低位宽"，**要么用旋转（付在线税），要么用曲率加权 / 零空间加性变换（不付在线税）**。本报告押后者 |

### 2.4 `A³ × 量化`

| 维度 | 判定 |
|---|---|
| **联合测量是否存在** | **✔✔ 有。** A³ 论文 Fig. 6 = **HQQ 4-bit 量化下，原模型 vs A³-LLaMA-3.1-8B 的 WikiText-2 PPL 对比** `[S]`。此外还有 A³ × KV 压缩、A³ × 微调、A³ × 混合秩分配 `[P]` |
| **数学兼容** | ✔ **两个乘数正交**：低秩改**形状**，量化改**位宽**。A³ 的解是白化 SVD（无学习参数），量化是逐组舍入 |
| **信息丢失** | ⚠ 两处独立叠加（形状逼近误差 + 量化误差）。论文的 Fig. 6 说明叠加后仍可用，但**未给"低秩 + 量化"的联合误差界** |
| **训练要求** | 两者都是 PTQ；A³ 需 **SlimPajama 校准**（BF16 模型、FP64 累加外积）`[S]` |
| **额外开销** | ⚠ **A³ 改变矩阵形状 ⇒ 在消费级运行时里 kernel 形状全变，没有现成快路径**。论文的吞吐数字是 **A100 + batch=2 + seq=2048** `[S]`，不是消费级 batch=1 |
| **潜在互斥（★ 本报告提出）** | ⚠ **降 head_dim 会改变 RoPE 的频率谱**（`ω_f = θ^{-2f/d}`）⇒ head_dim 128→64 同时改变基频与频率集合。**这不是函数等价的形状变换，而是改变位置编码语义。** 文献未处理。**旁证**：A³ 自身对**带 RoPE** 的情形改用 **CUR 近似**（Theorem 2/3 只覆盖无 RoPE）`[S]` |
| **消费端额外判据** | ⚠ A³ 的**收益维度是 FLOPs + 参数量 + KV 容量**——在 batch=1 消费级设备上 **FLOPs 几乎免费**（R1 实测有效带宽仅峰值的 46 %）⇒ **A³ 最值钱的那一项（FLOPs）在目标设备上最不值钱**；值钱的是"参数量 + KV 容量"那一半 |
| **总判定** | **✔✔ 有联合测量、数学正交、无硬互斥。** 但**消费端收益结构不利**，且有 head_dim × RoPE 的未处理风险。**这是四个配对里最"干净"的一个。** |

## 3. 额外发现的两条组合（任务书未指定，但本报告认为更重要）

### 3.1 `SpQt 的 zigzag 布局 × 任意低位宽格式` ⇒ **✔✔ 消费级唯一真正命中带宽轴的一条**

| 维度 | 判定 |
|---|---|
| **联合测量是否存在** | **✔ 已在 Q4_K 上完整实现并实测**（Q4_K 是 llama.cpp 自己的 K-quant 格式）`[P]`。格式无关性是设计意图（"沿列分组 + 行主序存储"可套到任何 group/block 量化格式） |
| **数学兼容** | ✔ 布局与位宽正交 |
| **信息丢失** | ✔ 稀疏跳过的权重本来就被阈值判定为可忽略（误差由阈值定义，不是由布局定义） |
| **训练要求** | 完全训练自由 + 需**离线重排权重**（自定义量化工具；70B 量化"less than five minutes on a commodity workstation"）`[P]` |
| **额外开销** | **一份非标准 GGUF**（stock llama.cpp / MLX / HF 都读不了）`[P]` |
| **潜在互斥** | ⚠ **batch>1 静默回退稠密**；**prefill 稠密且稠密路径未优化**（"does not yet employ a dedicated tiling-based GEMM optimization"）`[P]` |
| **★ 消费端实测** | **四个 Apple 芯片实测**：A19 Pro（75.8 GB/s）1.55× → M2（102.4）1.40× → **M2 Pro（204.8）1.26×** → **M2 Max（819.2）1.19×**（Llama-2-7B，Unified 50 %）`[P]`。**M4 Pro 是 273 GB/s ⇒ 外推约 1.2–1.3×** `[推算]` |
| **★ 对照** | **同一张表上 F16→Q4_K 值 2.4–2.6×**（M2 Max 上 F16 只有 Q4_K 的 0.38–0.42× 吞吐）`[P]` ⇒ **"更狠地量化"压倒"稀疏化"** |
| **总判定** | **✔✔ 唯一既有 Metal 实现、又有 Apple 实测、又真省字节的一条。** 但**收益被硬件带宽反向限制**，且质量代价（50 % 稀疏下 Llama-3-8B PPL 5.93→6.67）**大于** Q4_K 本身的代价（5.64→5.93）。**⇒ 支线，不是主线** |

### 3.2 `OSAQ（加性零空间变换）× 任意低位宽格式` ⇒ **✔✔ 最被低估的一条**

| 维度 | 判定 |
|---|---|
| **联合测量是否存在** | **△ 未找到与具体低比特格式（2-bit trellis / 4-bit affine）的联合测量** `[UNVERIFIED]` |
| **数学兼容** | ✔ **离线折叠进权重 ⇒ 与任何位宽、任何布局都不冲突** |
| **信息丢失** | ⚠ 加性变换**改变权重**（不是函数等价）⇒ **L3（任务能力近似保持）**；其"不影响任务损失"是 Hessian 意义下的局部论证 |
| **训练要求** | **闭式解，无资源密集训练、无迭代过程** `[P]` ⇒ 冻结权重完全适用 |
| **额外开销** | **零推理开销**（*"absorbed into the weights offline … no inter-layer transformations … no inference overhead"*）`[P]` |
| **潜在互斥** | ✔ **无。** 这是它与旋转族的根本分野：旋转是**正交的、必须在线撤销的**；OSAQ 是**加性的、可离线折叠的** |
| **总判定** | **✔✔ 唯一同时满足"零运行时开销"和"不与低位宽冲突"的离群点抑制方案。** 在本项目这类"必须自己写 Metal 后端"的处境下，**零运行时开销比 +1–3 个精度点更值钱**。**优先级应高于旋转族** |

## 4. 明确否证的"组合"

| 被否证的组合 | 判定 | 依据 |
|---|---|---|
| **"旋转 + 低位宽 = 两者收益相乘"** | **✘ 替代关系** | CurveTQ（旋转与原基底加权互为替代）`[P]`；RoPE-Aligned（RoPE 兼容族对量化不利）`[P]`；OSAQ（加性零方案零开销）`[P]` |
| **"Prox 的 1.99× 能直接搬到带宽受限设备"** | **✘** | Prox 速度测全在 **FP16**；**全文无字节计量**；散布输出通道在分组量化布局下 ≈0 % 字节节省 `[推算]` |
| **"FFN 稀疏在 Apple Silicon 上能拿到 1.5×+"** | **✘** | SpQt 在最弱的 A19 Pro 上 1.55×，**随带宽上升降到 M2 Max 的 1.19×**；M4 Pro 外推 1.2–1.3× `[P]`+`[推算]` |
| **"稀疏在 4-bit 之上再叠一层"** | **✘ 收益为负的组合** | SpQt 50 % 稀疏的 PPL 代价（+0.74）**大于** Q4_K 本身的代价（+0.29）；且低稀疏度时是 0.99×（比稠密还慢）`[P]` |
| **"动态逐 token 掩码 × 推测解码"** | **✘ 机制冲突** | 推测解码要求**同一请求在不同 batch 下的确定性**（batch-invariant 内核的前提），而逐 token 动态掩码使计算图随内容改变。**本轮未找到任何正面处理此冲突的论文** ⇒ 标 `[文献空白]` |

## 5. 组合审查的三条总体判断

1. **"已发表的联合测量"极少，且没有一格落在消费级。**
   全表只有两格 ✔✔：Prox × 稀疏注意力（NVIDIA，1.92×，且 LongBench 掉 3.4 分）与 A³ × 量化（HQQ 4-bit，只报 PPL）。**任务书点名的四组配对里，有两组（YAQA/CurveTQ × 稀疏布局、等价旋转 × 低位宽）根本不存在联合测量。**

2. **这一族最常见的失败模式，是把"名义工作量减少"当成"字节减少"。**
   三个独立测量在同一点上相遇：SpQt 的 **"Naive sparse" 基线 50 % 稀疏下 <0.2×**（约 5× 变慢）`[P]`；Proteus 的**"只有解码内循环避免不规则查表，ultra-low-bit PTQ 才有帮助"** `[P]`；R1 实测的**堆权重矩阵乘在 n=1 慢 29 %** `[M]`。**⇒ 判断一个组合是否值得做，第一问应该是"它减少了搬运的字节吗"，不是"它减少了计算量吗"。**

3. **在 24 GB 目标上，正确的排序是：位宽/格式 > 布局 > 稀疏 > 其余一切。**
   理由全部来自同硬件族的实测：F16→Q4_K **2.4–2.6×**（M2 Max）`[P]`；zigzag 布局式稀疏 **1.19–1.26×**（M2 Pro/M2 Max）`[P]`；散落通道式稀疏在分组量化布局下 **≈0 % 字节** `[推算]`；2-bit 需要的 trellis 解码器 **Metal 上不存在** `[S]`。
   **⇒ 与 R1 的独立结论（格式优先于位宽、位宽优先于稀疏、KV 压缩是支线）在两条完全不同的证据链上吻合。**
