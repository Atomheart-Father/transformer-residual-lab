# PART A — 「代数符号偏置修正」的精确审查

## A.1 先把 uzu 的实际重建公式解出来

**证据 1** —— `crates/uzu-engine/src/backends/cpu/kernel/activation_transform/trellis.rs`（CPU 参考实现）`[P]`：

```rust
let rotated = rotate_token(row, rht_factors, mixing, mixing_dimension);
let scale = min_max_symmetric_divisor(&rotated);
let mut token_column_group_sums = [0i32; COLUMN_GROUP_COUNT as usize];   // COLUMN_GROUP_COUNT = 4
for (column, (quantized, &value)) in quantized_row.iter_mut().zip(&rotated).enumerate() {
    *quantized = quantize_symmetric_i8(value, scale);
    token_column_group_sums[column % COLUMN_GROUP_COUNT as usize] += i32::from(*quantized);
}
column_group_sums_row.copy_from_slice(&token_column_group_sums.map(|sum| sum as f32));
```

⇒ **`column_group_sums[token*4 + c] = Σ_{j ≡ c (mod 4)} x_j`**，其中 `x_j` 是**旋转后并 int8 量化**的激活值。

**证据 2** —— `crates/uzu-engine/src/backends/metal/kernel/matmul/gemm/gemm_trellis.metal` 的 `TrellisEpilogue::store` `[P]`：

```c
const float4 group_sum = group_sums[token];
const int level_dot = biased_dot - int(trellis::WEIGHT_BIAS) * int(group_sum.x + group_sum.y + group_sum.z + group_sum.w);
const float4 offsets = float4(scale_and_offsets[1], scale_and_offsets[2], scale_and_offsets[3], scale_and_offsets[4]);
const float dot = float(level_dot) * scale_and_offsets[0] + metal::dot(group_sum, offsets);
output[token * output_row_stride + row] = bfloat(dot * row_scales[row] * activation_scale);
```

**证据 3** —— PR #900 新增常量 `[P]`：`MAX_BIASED_WEIGHT = 111; // 8 * 12 + 15` ⇒ level 域是 `[−54, +57]`（112 个值）。

### ⇒ 综合出的有效权重公式

把 (1)(2) 对齐（`biased_dot` = int32 MMA 累加器 = `Σ_k x_k · L[r,k]`，`L` 是解码出的有偏 level）：

```
out[t,r] = act_scale[t] · row_scales[r] · ( s·Σ_k x_k·L[r,k] − 54·s·Σ_k x_k + Σ_c o_c·Σ_{k≡c} x_k )
```

与 `out[t,r] = act_scale[t] · Σ_k x_k · W[r,k]` 对照，得：

> ### **W[r,k] = row_scales[r] · ( s·( L[r,k] − 54 ) + o_{k mod 4} )**
> 其中 `s = codebook[0]`（全矩阵 1 个标量）、`o_0..o_3 = codebook[1..4]`（全矩阵 4 个标量）、`row_scales[r]`（每输出行 1 个 f32）。

## A.2 与 Issue 给出的恒等式的对应

Issue 给的模型是 `w_i = α(q_i − c) + β`，结论 `Σ x_i w_i = α Σ x_i q_i + (β − αc) Σ x_i`。

在 uzu 中逐项对上：

| Issue 符号 | uzu 对应 | 备注 |
|---|---|---|
| `α` | `row_scales[r] · s` | 随行变化 |
| `q_i` | `L[r,k]`（解码出的有偏 level） | **不是被存储的量**（见 A.3） |
| `c` | `54 = WEIGHT_BIAS` | 全局常数 |
| `β` | `row_scales[r] · o_{k mod 4}` | **⚠ 随列类变化，不是常数** |

**⇒ 恒等式在 `β` 为常数时成立；uzu 用的是逐列类变化的 `β_k`，于是必须展开成四项**：

```
Σ_k x_k · β_k = row_scales[r] · Σ_c o_c · ( Σ_{k≡c mod 4} x_k ) = row_scales[r] · dot(group_sum, offsets)
```

**⇒ 这就是 `column_group_sums` 存在的唯一理由**：它就是那个"前置分组和"。恒等式本身完全成立，**且源码与推导逐项吻合**。

## A.3 ★★ 「省掉每权重 1 bit 符号位」——逐层审查

### (1) 范畴问题：uzu 里根本没有"每权重一个符号位"可省

`decode_biased_weights` 的路径是 **state → hash → 4 字节 → 每字节 1 个 level**（`WEIGHTS_PER_DECODE = 4`，PR #900 新增）。
⇒ **level 完全不被存储**，它是从状态链**合成**出来的。
被传输的只有：位流（states，2.0–3.0 bpw）+ 每输出行 1 个 f32 scale + 全矩阵 5 个 float 码本。

> **⇒ 在 uzu 上，"省一位符号位"没有落点：你不能省掉一个你根本没传的比特。**

### (2) 信息论问题：仿射重参数化是**信息保持**的，不是压缩

对任意仿射重参数化 `w = α(q − c) + β`（α ≠ 0），映射 `q ↦ w` 是**双射**。

> **⇒ 在相同码宽 n 下，n-bit two's complement 与 n-bit biased-unsigned 能表示的有符号值数量完全相同（都是 2ⁿ 个）。**
> **⇒ 所以"省一位"绝不能当成无条件的信息论结论 —— 这正是 Issue 的怀疑，且怀疑成立。**

### (3) ★ 最强反例：什么时候才真的省了一位？——只有对照方案**本来**多花了一位

| 对照表示 | 含独立符号位？ | "省一位"成立？ |
|---|---|---|
| n-bit **two's complement** | 否（n 位表示 2ⁿ 个有符号值） | **不成立** |
| n-bit **sign-magnitude**（符号位 + 幅值） | **是** | **成立** |
| **对称网格 + 显式符号位**（llama.cpp **IQ2_XS**：2-bit 无符号码 + **1 sign bit** + 子块 scale ⇒ 2.3125 bpw） | **是** | **成立**（省 0.3125 bpw） |
| **非对称网格 + 每块 min**（llama.cpp **Q4_K / Q2_K / Q3_K**：`d·q + dmin`） | **否** | **本来就没有符号位** |

> ### **★ 最强反例（也是 Issue 要的那个答案）**
>
> **llama.cpp 的 Q4_K / Q2_K / Q3_K 早就用"无符号码 + 每块仿射修正（`d·q + dmin`）"，一个符号位都不花**，而且**除了这一次乘加之外不需要任何额外代数**。
> uzu 版的增量只是把修正项从"每 32 个权重一对 (d, dmin)"改成"**全矩阵 4 个数（按列 mod 4）** + 每行一个 scale"——
> ⇒ **粒度更粗（表达力更弱）、参数更少（更便宜），但这不是"省了一位符号位"，而是"换了个参数化"。**
>
> **⇒ 真正能站住的命题只有一句**：
> > **"bias + group correction" 能省一位，当且仅当对照方案本来用 sign-magnitude / 显式符号位。**
> > 对 two's complement **不省**；对已经用 `d·q + dmin` 的 k-quant **更不省**（它们本来就没有符号位）。

### (4) 负载、前置分组和与真实成本 `[推算]`

| 项 | 成本 | 说明 |
|---|---|---|
| 权重侧载荷 | 位流 2.0–3.0 bpw + 每行 1×f32 + 全矩阵 5×f32 | 后两项可忽略 |
| 激活侧前置 | ① 旋转（Kronecker/Hadamard）② int8 量化 ③ **4 个列类和** ④ 1 个 scale | ①②④ 本来就要做 |
| **③ 的边际成本** | **每列 1 次加法**（4 个累加器轮转 ⇒ ≈0.25 add/column） | 便宜，但**不为零** |
| 激活侧额外存储 | 每 token 4×f32 + 1×f32 | decode 时需要 |

⇒ **⇒ "省下的那一位"的对价不在权重侧，而在激活侧**（维护 4 个列类和）。**这是一个成本转移，不是一个免费收益。**

### (5) ★ 一个容易被忽略的强约束：每行只有一个 f32 scale

`row_scales[r]` 是**每输出行一个**标量 ⇒ **编码器必须让每行的 level 均值与该行权重均值一致**，否则残差无法被 per-row scale 吸收。

**这解释了 `o_{k mod 4}` 为什么存在**：它用来修正**随列类变化、而 per-row scale 修不了的偏置**。

**而这正好与 incoherence 混合的列置换结构对上**：`rotate_token` 的输出布局是

```rust
rotated[hadamard_index * mixing_dimension + output_mixing_index] = hadamard_values[hadamard_index];
```

⇒ 一个**转置式（transpose-like）**重排，把原本相距很远的列排到了一起 ⇒ **"列 mod 4"这个分组恰好捕获了混合引入的结构**。

> ### **⇒ 可迁移的设计洞察（值得写进后续工作）**
> **修正项的分组粒度必须与 incoherence 混合的列置换对齐。** 换混合方式（换 block size、换 Hadamard↔Kronecker）而不改修正分组，就会丢掉这个结构优势。

### (6) ★ 数据依赖 vs 低位格码：这条论断在"低位格码"上完全落空

- uzu 的 level 是**哈希合成**的 ⇒ 分布**按构造**近似均匀，**不是数据自适应的**。真正的率失真问题完全落在"**状态链能否跟踪真实权重序列**"上。
- **仿射修正只去掉一个"列类均值"分量（4 个数）** ⇒ 它对主体分布**几乎没有帮助**。

> ### **⇒ 最强反例（对整条"省一位"论断的）**
> 设 level 域是一个**低位格码**（每组 16 个 level）：
> - **有符号格码**（16 个有符号 level）与 **无符号格码 + 组偏移**（16 个无符号 level + 1 个组偏移）**表达的信息量完全相同** —— 仿射修正只是重参数化，**不省任何东西**。
> - **只有当原方案用 sign-magnitude 时，偏移才能换回那一位。**
>
> **⇒ "代数修正省一位"的成立条件极其狭窄：要求对照方案在符号上花了额外比特。它与"低位"无关，与"网格"无关。**
> **⇒ 而 uzu 恰恰不处于这个狭窄条件里（它根本不存 level）⇒ 这个论断在 uzu 上没有落点。**

### (6bis) ★ 精确到字节的算术：**bias 在 uzu 上省 0 bit/权重**

WorkBuddy R4 的 `2026-10-r4-experiment-readiness.md` "纠错 2" 把它算到了字节级 `[P]`，与本文件 A.3 的结论**独立收敛**：

| 量 | 值 | 来源 |
|---|---|---|
| `WEIGHTS_PER_DECODE` | 4（一个 uint32 装 4 个权重） | PR #900 常量 |
| ⇒ 解码字里的密度 | **8 bit / 权重**（解码字是 uint32，**不是存储密度**） | 推导 |
| `MAX_BIASED_WEIGHT` | 111 ⇒ 有偏 level ∈ [0, 111]，**需 7 bit** | PR #900 常量 |
| 不做 bias | level ∈ [−54, 57] ⇒ **7 bit 幅度 + 1 bit 符号 = 8 bit** | 推导 |
| **存储侧** | trellis 状态转移，**2.0–3.0 bpw 与符号无关** | `[P]` |

⇒ **★ 结论**：**bias 在解码字里省 0 bit，在存储里也省 0 bit。**
**相对标准 2-bit 标量 / affine 编码（IQ2_XS 的 sign+码本、MLX affine 的 scale+bias），它省 0 bit/权重——那些方案没有"独立符号平面"，不存在"符号位"可省。**

**但它确实有两个真实效应，且都不是字节**：

| | 内容 |
|---|---|
| **收益（指令数）** | level 全非负 ⇒ **4 个 level 可一次 `as_type<uchar4>` 重解释为 `bfloat4`**，省掉 4 次有符号 int→float 转换 |
| **代价（内存）** | 需要 `column_group_sums`：**每 token 每 matmul 读 K/4 个 fp32；K = 5120 时 = 5.1 KB/token** |

⇒ **⇒ 它是"指令数收益 + 一个额外的 fp32 buffer"，不是字节收益；净效果未测。**
⇒ **⇒ 这比本文件 A.3 的表述更精确**：真正的收益不是"省一位"，而是"**让 level 全非负，从而能一次重解释**"。

### (7) 术语层面的更正（建议替换 WorkBuddy R3 的措辞）

> **原措辞**：*"省掉每权重的 1 bit 符号位。在 2 bpw 下 1 bit 是 50 % 的额外开销——这是这套方案能做到 2.0 bpw 的关键之一。"*
>
> **建议替换为**：
> *"uzu 的 level 域被限制在**非负偏置区间 [−54, +57]**（`MAX_BIASED_WEIGHT = 111`），把偏置/符号交给一个**全矩阵共享的、按列类（mod 4）分解的仿射修正项**来承担；代价是激活侧必须为每个 token 维护 4 个列类和（每列 1 次加法）。*
> *这与"省一位符号位"**不是同一件事**：前者是**表示域的重排 + 共享修正**，后者是**码宽的减少**。只有在对照方案含显式符号位（如 IQ2_XS 的 sign bit）时两者才等价；对 two's complement 与对 Q4_K 系的 `d·q + dmin` 都不等价。"*

# PART B — 评估门槛的重审

## B.1 被审门槛的原文（WorkBuddy R3 errata，来源标注 Issue #4 P0-1）`[P]`

> **质量关卡必须独立设置**（速度通过不代表可用）：
> - 2-bit 的 held-out PPL ≤ **1.15 ×** 同模型 4-bit 的 PPL；
> - 一个下游任务（如 **5-shot MMLU 子集**或 wikitext 上的 **top-1 一致率**）下降 ≤ **2 分**；
> - 任一不通过 → 该位宽直接淘汰，速度数据仅作记录。

## B.2 六个问题

### 问题 1：PPL 是**分布代理**，不是**能力代理**

- PPL = token 级平均 NLL。它对 **tokenizer 对齐、表面措辞、频率分布**极其敏感，却对 **推理正确性、指令遵循、工具调用合法性、多步一致性**几乎不敏感。
- **系统性偏差**：一个把答案改写得更啰嗦但**仍然正确**的量化模型，PPL 明显变差；一个把答案改短但**错**的模型，PPL 可能变好。
- ⇒ **PPL 在"表面统计"上过度敏感，在"能力"上不敏感 —— 恰好与门槛的目的相反。**

### 问题 2：★★★ 门槛的"松紧"与"统计力"**方向相反**

| 量 | 类型 | 样本量 | 统计力 | 门槛 | 
|---|---|---|---|---|
| held-out PPL | 连续 | 数千～数万 token | **极强**（同分布内 1.15× 几乎必然"显著"） | **紧**（1.15×） |
| 5-shot MMLU 子集 | 离散 | 常见 n = 200～1000 | **弱**：n=1000, p≈0.5 时二项 SE ≈ **1.58 分**；n=250 时 **≈ 3.16 分** | **≤2 分** |

⇒ **在 n = 250 的子集上，"下降 ≤ 2 分"小于 1 个标准误 ⇒ 这条门槛在统计上没有任何检出力。**
⇒ **⇒ 把统计力最强的量设成紧阈值、把统计力最弱的量设成"≤2 分"却不用 CI —— 结论会随子集大小漂移。**

### 问题 3：三个阈值都**没有推导**，且量纲不可比

- 1.15× PPL ≈ **+14 % NLL**；"−2 分准确率"与"+14 % NLL"之间**没有通用换算**。
- ⇒ 三个阈值必须**各自**配 (a) 统计模型、(b) **最小可检测效应 MDE**、(c) 与决策规则的绑定；不能并列成一个"总体印象"。

### 问题 4：★ 「下降 ≤ 2 分」（**绝对分**）对不同基线能力**不公平**

| 基线 | 量化后 | 绝对降 | 相对降 |
|---|---|---|---|
| p = 90 % | 85 % | 5 分 | **5.6 %** |
| p = 60 % | 58 % | 2 分 | **3.3 %** |

⇒ 同一阈值对高基线**过松**、对低基线**过紧**（实际是反的：高基线的 5.6 % 相对退化被放过，低基线的 3.3 % 相对退化被拦住）。
⇒ **⇒ 建议改为"相对退化 + 绝对退化"双阈值，或改用配对检验的效应量。**

### 问题 5：★ MMLU 的三重偏置

1. **MMLU 是 4-shot**（5-shot 仅限子集）；**few-shot 示例会改变格式与正确率** ⇒ "5-shot 的 2 分"与"0-shot 的 2 分"**不可比**。
2. **MMLU 只测选择，不测生成** ⇒ 能力上限被"选项已给出"掩盖；**指令跟随、代码、数学答案生成在 MMLU 上几乎测不到**。
3. **子集选择偏差**：若子集是"有代表性的"，则 **"下降 ≤ 2 分"是保守的**；但若子集是为省时间挑的**易题**，则该门槛**几乎没有信息量**。

### 问题 6：★★ 「top-1 一致率 ≥ 90 %」是最危险的一条

- 它测的是**量化前后 argmax 是否相同**，即**决策边界的敏感性**，**不是能力**。
- **既会假阳性也会假阴性**：
  - **假阳性（惩罚等价答案）**：同一能力的两种表述在 top-1 上不同 ⇒ 扣分。⇒ **与 Issue 关心的"误伤等价答案"直接相关。**
  - **假阴性**：一致率 100 % 但都错。
- **更根本的一致性问题**：**一致率与 ±2 分准确率不是同一个量。** 若 10 % 的 token 位置 argmax 变了，**其中有多少落在关键决策点？一致率本身不区分。**
  ⇒ **⇒ 一致率应当降级为"诊断量"，不作为门禁。**

## B.3 ★★ 通用性：这组门槛最根本的问题

> **这些门槛全部绑定在"选择题 + 困惑度"上 ⇒ 它们测的是"表面统计保持"，而不是"数学 / 编程 / 工具使用能力保持"。**

| 能力轴 | held-out PPL | 5-shot MMLU | top-1 一致率 |
|---|---|---|---|
| **数学推理** | 弱（token 级 NLL 对推理链正确性不敏感） | 弱（选择 ≠ 生成） | 不测能力 |
| **编程** | 弱（代码 NLL 与"可编译/通过测试"相关性弱） | **≈0**（MMLU 无代码） | 不测能力 |
| **工具使用** | 弱（JSON 合法性对 NLL 几乎无影响） | **≈0**（MMLU 无工具） | 不测能力 |
| 长上下文信息恢复 | 中（远处 token 的 NLL 被平均稀释） | 否 | 否 |
| 多轮指令保持 | 弱 | 否（单轮） | 否 |

⇒ **⇒ 即使三条门槛全部通过，也不能支持"强模型能力保持"的结论。**

## B.4 ★★ 分阶段质量测试方案设计（只设计，不执行）

**总原则：先验机制、后验能力；每一步都必须有"能推翻结论"的力；门禁与速度必须分离并预注册。**

### Stage 0 — 机制层（0.6B，本机，秒级～分钟级）

**目标：在花钱下载 27B 之前，先确认数学机制成立，并给量化器本身定一个误差棒。**

| 编号 | 探针 | 做法 | 判据 | 为什么它能推翻结论 |
|---|---|---|---|---|
| **S0.1** | **精确等价性** | 对"数学等价"变换（OSAQ 式离线加性折叠、把旋转变换折叠进权重），在固定 prompt 集上比较**反量化后的权重**与**logits** | **反量化权重应逐位相同**；logits 的差异应 ≤ bf16 舍入 | 若不等价 ⇒ 这一族"无损"的说法作废 |
| **S0.2** | **★ 量化器方差探针** | 用 **≥3 组互不相交的校准抽样**（例如不同域的 256-token 切片）**各自**量化同一权重 | 报告**逐层相对误差的跨抽样标准差**与**下游指标的跨抽样区间** | **这是本方案最重要的一条**：它给出**量化器自身的噪声底**，从而让"下降 ≤ 2 分"变成"下降是否超出噪声底" |
| **S0.3** | **逐层误差谱** | 对每层算 `‖ΔW‖/‖W‖` 与 `‖ΔW·X_cal‖/‖W·X_cal‖`；**按层类型分组报（q/k/v/o、gate/up/down、embed、head），不报总平均** | 定位**误差最大的层**（通常是 down_proj 与 embedding） | 若误差集中在某类层 ⇒ 门禁应按层设计，而不是全局一刀切 |
| **S0.4** | **比特级确定性** | 同一 prompt、同一 kernel 跑 3 次 | 输出应**逐 token 相同** | 若不确定 ⇒ 所有后续对比都被噪声污染 |
| **S0.5** | **端到端分布距离** | 在校准集与 held-out 集上算 logits 的 KL（FP16 为参照） | 报告**按 token 位置的 KL 曲线** | 定位"哪一步开始崩"，而不只是"最终掉了多少" |

**⚠ 0.6B 上不能验证什么（必须写进结论）**：真实 27B 模型的 FFN/attention 比例、embedding 占比、激活分布尾部的形状、真实长上下文行为、以及**任何绝对数值阈值**（0.6B 的 PPL 不可外推到 27B）。

### Stage 1 — 0.6B 上的能力形状（小样本，有反证力）

| 编号 | 任务 | 样本量 | 主指标 | 辅助指标 |
|---|---|---|---|---|
| **S1.1** | GSM8K（**CoT 生成**） | **250 题** | **答案级等价判定**（规范化后：`1/2`≡`0.5`、`2π`≡`6.28`、去单位、trim）后的通过率 | 推理链是否可解析 |
| **S1.2** | HumanEval 子集 | **60–100 题** | pass@1（标准测试框架） | 生成是否可编译 |
| **S1.3** | **工具调用合法性** | **100 条合成指令** | **JSON schema 合法性** + **参数正确性**（两项**分开报**） | 工具选择是否正确 |
| **S1.4** | **格式对照项**（**关键对照**） | 与 S1.1 同题 | **同一提示词下的格式依从率** | —— |

**S1.4 的作用（这是"误伤等价答案"的直接对策）**：
把"**答案错了**"与"**格式变了**"**分开测量**。
⇒ 若 S1.1 通过率持平而 S1.4 明显下降 ⇒ 退化在**表面**（可接受/可修）；
⇒ 若 S1.1 下降 ⇒ 退化在**能力**（不可接受）。
⇒ **没有这一项，"下降 ≤ 2 分"就无法归因。**

### Stage 2 — 本地较大真实模型（**真正的门槛**）

- 用**本地已有的**较大模型（先确认哪些模型真的在本地，见 §B.5 的前置核对）。
- **同样三件套**：PPL（文档级 CI）＋ 一个**生成式可判等**任务 ＋ 一个**工具调用**任务。
- **样本量与 MDE**（配对设计，见下表）。
- **必须与 4-bit 基线同口径**：同 prompt、同 few-shot 示例、同解码参数、同判分器。

### Stage 3 — 只在必要时做的跨模型确认

- 只在 Stage 2 通过后做；**只做 1–2 个**；用来区分"方法本身的问题"与"这个模型的偶然问题"。

## B.5 统计纪律（把方案变成可判定的规则）

**(a) 配对，不是非配对。** 量化前后跑**同一批题** ⇒ 用 **McNemar 精确检验**（二元结果）或**配对 bootstrap**（连续量）。配对设计在 n=250 时能检出**非配对设计检不出的**差异。

**(b) CI 的单位是"文档"，不是"token"。**
同一文档内的 token 高度相关 ⇒ 逐 token 的 CI 会**严重低估**不确定性。
⇒ **几乎所有量化论文报告的 PPL 都没有文档级 CI** —— 这是一个系统性的、被普遍忽略的统计缺陷。

**(c) 样本量与 MDE（二项，配对，α=0.05 双侧，power=0.8 的量级）：**

| 配对不一致率 ψ | n = 100 | n = 250 | n = 500 | n = 1000 |
|---|---|---|---|---|
| 0.10 | 9.8 分 | 6.2 分 | 4.4 分 | 3.1 分 |
| 0.15 | 7.3 分 | 4.6 分 | 3.3 分 | 2.3 分 |
| 0.20 | 5.7 分 | 3.7 分 | 2.6 分 | 1.8 分 |

⇒ **⇒ "≤2 分"只有在 n ≥ 1000 且不一致率 ≤15 % 时才有约 80 % 的检出力；在 n = 250 时它连 3.7 分都检不出。**
⇒ **⇒ 门槛必须与 n 一起写死**；若只能做小样本，**就应该把门槛设成"必须优于噪声底"而不是一个绝对分**。

**(d) 要重复的对象是"校准抽样"，不是"解码种子"。**
确定性解码下重复解码种子**没有信息**；真正的方差来源是**量化器的校准抽样**。
⇒ **最小重复次数：≥3 组独立校准抽样**，所有下游数字报**跨抽样的区间**，而不是单次值。

**(e) 预注册。** 在看到结果之前写死：阈值、n、检验方法、CI 水平、停止规则、以及"**什么结果会推翻这个方案**"。
⇒ **本方案自己也要能被推翻**：例如 S0.2 若显示跨抽样标准差 > 预期门槛的一半，则"≤2 分"的判据作废，必须放宽或改用噪声底相对判据。

## B.6 对 WorkBuddy 三条门槛的逐条替代建议

| 原门槛 | 主要问题 | 建议替代 |
|---|---|---|
| held-out PPL ≤ 1.15× 4-bit | 表面敏感 / 能力不敏感；无 CI 单位；无文档级 bootstrap | **保留为必要条件**（WorkBuddy R4 的更严版本是 **"PPL 由 ΔNLL 换算，只作展示，不作判据"**），但加两条：① **文档级配对 bootstrap 的 95 % CI 下界 ≤ 1.10×**；② **与下游门槛取"交集"而非"并列"**（PPL 通过但下游超噪声底 ⇒ 判不过） |
| 5-shot MMLU 下降 ≤ 2 分 | 小子集无检出力；MMLU 只测选择；shot 数改变语义；绝对分对基线不公平 | ① 换成**生成式可判等任务**（如 GSM8K 答案判定）+ **配对 McNemar**；② 门槛写成 **相对退化（如相对降幅 ≤ 1 %）与绝对退化双阈值**；③ **明确写死 n 与不一致率假设**；④ MMLU 降级为"广度参考"，不作为唯一门禁 |
| top-1 一致率 ≥ 90 % | 测决策边界敏感性；对等价答案惩罚；与"−2 分"不是同一个量 | **降级为诊断量**（报告但不设门禁）。若要保留一个"输出稳定性"门禁，改用**答案级等价判定**（规范化后比较），并与 S1.4 的格式对照项**联合判读** |

## B.7 补充：一个容易被忽略的"表面统计"陷阱

**tokenizer 对齐**：若量化改变了 logit 的**排序**，输出 token 可能整体切换 ⇒ **PPL 与一致率同时恶化，但能力没变**。
⇒ **对策**：在 Stage 0 就测**logits 的 KL**（S0.5）与**top-1 变化率**（作为诊断量）；在 Stage 1 用 **S1.4 格式对照**把"格式漂移"与"能力退化"分开。
⇒ **同时**：`top-1` 变化率应与 **能力指标**联合报告，**单独出现时没有判据价值**。
