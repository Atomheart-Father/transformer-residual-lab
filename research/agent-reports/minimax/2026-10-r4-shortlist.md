## 0. 本轮的收敛逻辑（先说清楚"为什么只有两条"）

Issue 要求"数学上最有希望**且最容易同 Metal 执行**"。把这两条约束合起来，候选必须同时满足：

| 约束 | 含义 | 排除掉什么 |
|---|---|---|
| **离线** | 变换在权重上离线完成，**不引入任何在线算子** | 一切需要在线撤销的旋转/正交变换（QuaRot/SpinQuant 式） |
| **可直算码** | 解码是**少量算术**，不需要大码本查表 | 一切 LUT 型 VQ / trellis（escha-port 实测查表产生 **13× 于权重的 L2 流量**） |
| **Metal 上今天就有内核** | 不需要写新内核 | 一切 fork-only 的自定义格式（SpQt 的 zigzag 是 fork-only ~8K 行） |
| **冻结权重可用** | 不需要重训 | ParetoQ / BCJR-QAT / **Mirai S 公开模型（QAT 产物）** |

⇒ **这四条同时成立的候选，事实上只有两个来源**：
**① 离线可折叠的变换**（OSAQ 式加性零空间变换）**× 可直算码**；
**② 本身就产出可直算码的量化器**（GSQ → GGUF Q2_K）**× 可直算码**。

⇒ **trellis 路线在本轮不入选**，理由见 §3。

## 1. 候选一：OSAQ 式加性零空间变换 × 4-bit 仿射码

### 1.1 精确内容

| 项 | 内容 | 等级 |
|---|---|---|
| **变换** | OSAQ `2605.04738v2`（2026-05-06，Li / Dong / Liu / Zhang / Gu，arXiv comment 标 ICML 2026） | `[P]` |
| **机制** | 在 **Hessian 稳定零空间**上做**加性**权重变换，抑制离群点 | `[P]` |
| **运行时税** | **0** —— 变换**离线折叠进权重**，不引入层间变换、不引入推理开销 | `[P]` |
| **码** | **4-bit 仿射码**：`llama.cpp` 的 Q4_K（每 32 权重一对 `d`/`dmin`）或 MLX 的 group-64 对称仿射 | `[O]`（R2 §8.1 已核部署面） |
| **Metal 内核** | **今天就有**（llama.cpp `ggml-metal`、MLX `quantized.h`），**无需写一行新内核** | `[P]` |

### 1.2 为什么它排第一

- **它是这一族里唯一同时满足"零运行时开销"和"不与任何位宽冲突"的变换**（R2 §10 判断 5）。
- R2 §4 记录的分野是结构性的：**旋转是正交的、必须在线撤销的；OSAQ 是加性的、可以离线折叠进权重的。同样达到抑制离群点，OSAQ 的运行时税是 0。**
- **它与"可直算码"零冲突**：加性变换改变的是**权重本身**，码的解码式（`d·q + dmin`）完全不受影响。
- **⇒ 整条链上一行新内核都不需要写**，这是"最容易同 Metal 执行"的字面含义。

### 1.3 数学等价 vs 经验质量近似（必须分清）

| 环节 | 性质 |
|---|---|
| **把变换折叠进权重** | ✅ **数学等价（精确）**：折叠后的权重就是变换后的权重本身，**没有近似** |
| **抑制离群点 / 零空间投影** | ⚠️ **经验质量近似**：零空间由**校准数据估计的 Hessian** 得出 ⇒ 只在**校准分布附近**近似保持该层的输出，**不是数学恒等**（L4 级） |
| **4-bit 仿射码** | ⚠️ **有损**（L4） |

⇒ **⇒ 它不是"无损"方法，任何声称它无损的说法都要驳回。**

### 1.4 收益在哪里（以及不在哪里）

- **它不产生任何加速。** 字节数不变、FLOPs 不变、串行轮次不变 ⇒ **⇒ 不得为它报任何加速倍数。**
- **它的收益是"在同一位宽下多保住多少能力"，以及"把位宽再降一档是否变得可行"。**
  ⇒ 这与本项目的目标一致（24 GB 上装下 20–30B 强模型），但**卖点是可行性，不是速度**。

### 1.5 最强反证（按杀伤力排序）

1. **★ 与仿射码的交互可能反噬。** 加性变换会改变**每行/每组的均值与动态范围**。4-bit 仿射码的 `d`（scale）由组内幅度决定、tail 被拉长 ⇒ **某些组的 scale 变大 ⇒ 该组实际可用比特变少**。**这可能让"离群点被压下去"的好处被"其他组变差"抵消。** ⇒ 必须用质量门槛文档的 **S0.3 逐层误差谱**直接验证，**不能靠论证**。
2. **★ 校准集与评测集不匹配 ⇒ 收益可能变成损失。** 零空间是**校准分布**上的；换一个分布，投影方向就未必是"该压的方向"。**GSQ 已在 Kimi-K2.5 上实测到校准域损伤**（OpenThoughts 偏数学/代码 ⇒ GPQA Diamond 下降）⇒ **这不是假想风险，是已发生过的同类失败。**
3. **★ venue 状态存疑。** arXiv 记录标 ICML 2026，但五种拼写在 OpenReview / HF papers / arXiv export / GitHub / ICML 2026 program 页**全部零命中**（同场对 "QTIP" 返回 129 条）⇒ **本报告按 `[P]` 采用 arXiv 记录、对 venue 降级**（R2 §11）。
4. **★ 无与具体格式的联合测量。** R2 §11 记录："OSAQ 与具体低比特格式（2-bit trellis / 4-bit affine）的联合测量"**未核实** ⇒ **本候选是"零冲突"推出来的，不是"联合测过"推出来的。**
5. **规模外推未知。** Hessian 零空间的有效性随模型规模/宽度变化 ⇒ **0.6B 的结论不能外推到 27B。**

### 1.6 Kill condition（可低成本证伪）

> **在目标模型上跑 S0.3（逐层误差谱）**：
> 若**离群点最严重的那些层的相对误差没有下降**（与同码率 4-bit 基线比），⇒ **变换没起作用 ⇒ 候选一作废。**
> 附加条件：若 S0.2（≥3 组独立校准抽样）显示**逐层误差的跨抽样标准差** ≥ 预期收益的一半 ⇒ **收益小于噪声 ⇒ 该候选必须先解决方差问题。**

## 2. 候选二：GSQ（Gumbel-Softmax 标量量化）× Q2_K（2-bit 可直算路径）

### 2.1 精确内容

| 项 | 内容 | 等级 |
|---|---|---|
| **量化器** | GSQ `2604.18556v2`（2026-04-20）《GSQ: Highly-Accurate Low-Precision Scalar Quantization for LLMs via Gumbel-Softmax Sampling》；仓库 `IST-DASlab/GSQ`（**Apache-2.0**，最后提交 `03fc16484c36`，2026-07-05） | `[P]`/`[O]` |
| **机制** | 用 **Gumbel-Softmax 采样**逼近舍入的松弛分布 ⇒ 目标是**分布正确**而非逐点最优 | `[P]` |
| **产物** | **GGUF K-Quant（2.13 bpp，位级兼容标准 `Q2_K`）**，*"runs unchanged on llama.cpp / Ollama / LM Studio"* | `[O]`（R2 §8.1） |
| **Metal 内核** | **今天就有**（llama.cpp 的 K-quant 内核） | `[P]` |
| **vLLM** | 走 `compressed-tensors` 配置，论文与仓库**声称**自动检测，**未验证** | `[UNVERIFIED]` |

### 2.2 为什么它排第二（而不是被排除）

- **它是这一族里唯一有"已验证可用路径"的**：产物在 llama.cpp / Ollama / LM Studio 上**原样跑**，且 **R1 已记录其模型卡的 Apple 侧数字**（Q2_0 2.40 bpw / 66.4 GB / AIME25 96.67 vs BF16 100.00 / 354 GB；Q2_0 **367.49 prompt t/s、93.79 decode t/s、6.70 s** vs IQ2_XS 108.19 / 70.30 / 12.68 s）`[O]`（**本轮未重新核对其硬件口径** `[未核实]`）。
- **它是"可直算码"路线的最强实测存在**：2-bit 走 K-quant 的 `d·q + dmin`，**没有查表、没有状态链**。

### 2.3 数学等价 vs 经验质量近似

| 环节 | 性质 |
|---|---|
| **Gumbel-Softmax 舍入** | ⚠️ **经验质量近似**：采样的是松弛化的舍入分布 ⇒ **目标是最优分布近似，不是逐点最小误差**；**且它是随机的**（见 2.5 第 3 条） |
| **Q2_K 打包** | ⚠️ **有损**（L4）；**位级兼容标准格式** ⇒ 不需要任何专用解码器 |

### 2.4 最强反证（**必须放在最前面，因为这条最重**）

1. **★★ 质量起点已经落后。** GSQ 自表（70B zero-shot）：**FP16 78.99 → GSQ 2-bit 75.57**，且 **GSQ 仍比 QTIP 低 1.7 点** `[P][O]`。
   ⇒ **⇒ 如果目标是"在 27B 上保住强模型能力"，GSQ 2-bit 的起点就比 trellis 族低 1.7 分 —— 这不是"部署更省"的取舍，而是"质量更差 + 部署更省"的取舍。**
2. **★★ 校准域损伤已被实测到（不是假想）。** GSQ 在 **Kimi-K2.5 2-bit 上 GPQA Diamond 下降**，原因是校准集（OpenThoughts）偏数学/代码 `[P]`。
   ⇒ **⇒ 这恰恰是"分布保持 ≠ 能力保持"的一个真实实例**，与质量门槛文档 Part B 的批评完全一致：**一个在分布上合格的量化器，在特定能力轴上可以明显退化，而 PPL 门禁看不见。**
3. **★★ Gumbel-Softmax 是随机采样 ⇒ 量化器方差是一等公民。** 任何单次结果都不足以判定 ⇒ **必须先跑 S0.2（≥3 组独立校准抽样）**，否则整个候选的评估都不可信。
4. **没有性能杠杆。** 既然码是现成的 Q2_K、内核是现成的，**这条候选的全部收益都在"能否装进 24 GB"和"质量掉多少"**，**没有可写的内核、也就没有加速故事**。
5. **vLLM 侧未验证**（`compressed-tensors` 自动检测只是"声称"）。
6. **硬件口径待核**：R1 记录的 93.79 decode t/s 来自模型卡位宽扫描，**本轮未重新核对其硬件**；与本轮引用的 Mirai S "base M4 上 4 tok/s" **不可直接同口径比较**（芯片型号与软件栈都不同）。

### 2.5 Kill condition（可低成本证伪）

> **先跑 S0.2（≥3 组独立校准抽样）**：
> 若**逐层误差或下游指标的跨抽样标准差 ≥ 预期门槛的一半** ⇒ **单次结果不可信 ⇒ 必须先降方差（Gumbel 采样次数 / 退火）再谈候选。**
> 附加条件：若 S1.4（格式对照）显示退化**全部**来自格式而非答案正确性，且 S1.1 通过率持平 ⇒ **能力未退化**（可接受）；反之若 S1.1 通过率超出噪声底地下降 ⇒ **候选二在"保住强模型能力"这一目标上作废**（但它在"省字节"这一目标上仍成立）。

## 3. 明确**不**推荐的路线（并说明理由，避免"造机会"）

### 3.1 Trellis / 2-bit trellis 路线 —— 本轮**不进 shortlist**

**理由全部来自本轮的新证据**（不是"没实现过"）：

| 理由 | 证据 |
|---|---|
| **★ 在目标芯片上解码器极慢**：Mirai S（2.4 bpw）在 **base M4 上 ≈4 tok/s** decode / 13 tok/s prefill；而 **GSQ Q2_0（2.40 bpw）模型卡自报 93.79 decode t/s** ⇒ **同位宽差 ~23×**（**口径不同，不可直接同芯片比较**） | 模型卡 `[O]` / R1 记录 `[O]` |
| **★ 公开模型是 QAT 产物**，不满足"冻结权重"前提 | `physical_package_report.json` 的 candidate 含 "**+ QAT 38zmrr2**"；`loader_validation.json` 的 dense 参照为 `q38zmrr2-package-**qat**-v1` |
| **★ 质量完全未公开测量**（无 PPL、无任务分数） | 模型仓 46 个文件中无任何质量产物；`speedcheck.py` 只测速度 |
| **★ 编码器不公开**（第三方只能消费不能生产） | `recover_p8zm_codes.py` GitHub 0 命中；fit 产物在私有路径 |
| **两个 PR 都未合并** | uzu #899 / #900、lalamo #364 全 OPEN |
| **依赖关系脆弱** | lalamo #364 点名依赖 uzu #899 及其 #925 packing update |

⇒ **⇒ 结论**：**trellis 是"格式对、解码器贵"的路线；在 Metal 上它当前的瓶颈不是格式而是内核实现。** 值得跟踪，但**不是一个当前可执行的候选**。
⇒ **⚠ 修正我 R3 的一个说法**：我曾说"Metal 上没有 trellis 内核"——**现在有了**（uzu，且随模型仓发布预编译二进制，PR #900 解除 M4 门控）。**正确的说法是"有内核，但慢"。**

### 3.2 RCO —— 不进 shortlist

| 理由 | 证据 |
|---|---|
| **适用区间极窄**：优势**只存在于极低位宽区间**（≥3.5 bit 时 *"surrogate methods already solve the problem well"*） | `[P]`（R2 §3.8） |
| **求解成本高**：离散求解器**纯 Python**（270–1783 ms/call）；完整搜索 **62 分钟 – 14 小时** | `[P]` |
| **与 GSQ 重叠**：二者在同一区间竞争，而 **GSQ 的部署面宽得多**（GGUF 原样跑 llama.cpp） | `[O]` |
| **机制不同**：RCO 是"精确预算约束下的分配器"，不产出可直算码 | R2 §8.2 |

⇒ **⇒ 在"最多两条"的额度下，RCO 被 GSQ 挤出。**

### 3.3 "把 uzu 的 Metal Trellis 接到 llama.cpp / MLX"

- **许可证没有障碍**（MIT，vs QTIP 的 GPL-3.0）——**但这不是数学候选**：
  - 没有模型、没有编码器（§3.1）、质量未测；
  - 需要把 uzu 的自定义格式翻译成 llama.cpp/MLX 能吃的格式 ⇒ **这是工程量，不是"数学上最有希望"**；
  - **而且没有性能依据**：4 tok/s（M4）的路径不值得移植。

### 3.4 "给 uzu 提 PR 打开 M1–M4 的门"

- **PR #900 已经在做这件事**（OPEN）。我们重复做没有增量。
- **且不该做**：在 `simdgroup_matrix<int8_t,8,8>` 的 Apple9 可用性核清之前改门控，等于制造一个可能跑不动的路径（WorkBuddy 的 C-04 只核了 fp8/half 变体）。

## 4. 两条候选的并列对照

| 维度 | 候选一：OSAQ × 4-bit 仿射码 | 候选二：GSQ × Q2_K |
|---|---|---|
| **位宽** | 4-bit（可再降一档，但未验证） | **2-bit**（2.13 bpp） |
| **字节收益** | 0（相对无变换的 4-bit） | 4.25 → 2.13 bpw |
| **新 Metal 内核** | **0 行** | **0 行** |
| **运行时开销** | **0**（离线折叠） | 0 |
| **公开可获取的产物** | ❌ 未核实（OSAQ 无公开模型） | ✅ **有**（GGUF Q2_K，llama.cpp 原样跑） |
| **独立质量数字** | ❌ 无 | ⚠️ 模型卡级（70B zero-shot 78.99→75.57；且比 QTIP 低 1.7） |
| **已知失败模式** | 校准域不匹配 ⇒ 收益反转；与仿射 scale 的交互可能反噬 | **校准域损伤已实测**（Kimi-K2.5 GPQA 下降）；**随机采样 ⇒ 方差大** |
| **冻结权重可用** | ✅ 是 | ✅ 是 |
| **性质标签** | 折叠=**数学等价（精确）**；零空间投影=**经验质量近似**；量化=有损 | Gumbel-Softmax=**经验质量近似（且随机）**；量化=有损 |
| **不成立的说法** | "无损"、"更快" | "无损"、"更快"、"2-bit 质量不掉" |
| **Kill condition** | S0.3：离群点层误差未下降 ⇒ 作废 | S0.2：跨抽样标准差 ≥ 门槛一半 ⇒ 先降方差；S1.1：超出噪声底地下降 ⇒ 在"保能力"目标上作废 |
| **外推限制** | 校准依赖、规模依赖；**0.6B 不可外推 27B** | 同上；且 93.79 t/s 的硬件口径本轮未核对 |

## 5. 本轮对 R1–R3 的净结论（一句话版）

> **在 24 GB Apple Silicon 上，2-bit 的瓶颈是解码器实现质量，不是位宽本身：同一 2.4 bpw，Mirai S 在 M4 上 4 tok/s，GSQ Q2_0 模型卡报 93.79 tok/s，差约 23×。因此本轮收敛到的两条候选，都刻意选择了"零新内核 + 零运行时开销"的一侧：OSAQ 式离线加性变换（买质量）与 GSQ 的 Q2_K 路径（买字节）。**
> **trellis 是格式层面的正确方向，但当前不是可执行的候选。**
