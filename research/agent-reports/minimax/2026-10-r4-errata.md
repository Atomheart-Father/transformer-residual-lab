## E1 【P0 · 事实错误】"2.13 bpp" 与 "标准 Q2_K" 是两回事

### E1.1 一手复核：llama.cpp 的 Q2_K 真实 bpw

`https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h` `[P]`：

```c
// 2-bit quantization
// 16 blocks of 16 elements each
// Effectively 2.625 bits per weight
typedef struct {
    uint8_t scales[QK_K/16]; // scales and mins, quantized with 4 bits
    uint8_t qs[QK_K/4];      // quants
    GGML_EXTENSION union {
        struct { ggml_half d; ggml_half dmin; } GGML_COMMON_AGGR_S;
        ggml_half2 dm;
    } GGML_COMMON_AGGR_U;
} block_q2_K;
static_assert(sizeof(block_q2_K) == 2*sizeof(ggml_half) + QK_K/16 + QK_K/4, "wrong q2_K block size/padding");
```

`QK_K = 256` ⇒ `sizeof = 4 + 16 + 64 = 84 B / 256 权重 = **2.625 bpw**` ⇒ **llama.cpp 自己的注释就写着 "Effectively 2.625 bits per weight"。**

**同文件的官方 bpw 表** `[P]`：

| 格式 | llama.cpp 注释原文 |
|---|---|
| Q2_K | **2.625** bits per weight |
| Q3_K | **3.4375** bits per weight |
| Q4_K | **4.5** bits per weight |
| Q5_K | **5.5** bits per weight |
| Q6_K | **6.5625** bits per weight |

### E1.2 一手复核：GSQ README 里 2.13 与 Q2_K 各指什么

`https://github.com/IST-DASlab/GSQ` `[P]`：

> *"GSQ compresses **Kimi-K2.5** from ~4.5 bpp down to **2.13 bpp** while preserving most of the model's reasoning, coding, and long-context behaviour."*
> *"**Llama-3.1-Instruct, 2.13 bpp** (zero-shot avg over ARC-C/E, HellaSwag, PIQA, Winogrande)"*
> *"**Qwen3-8B GGUF K-Quant**: Starting from public Unsloth GGUF checkpoints, GSQ refines the discrete assignments and projects the result back into **the same K-Quant format**, so the optimized checkpoint runs unchanged on llama.cpp / Ollama. The gains are largest in the aggressive **Q2_K** setting (avg score 50.03 → **56.28**)."*

⇒ **两条不同的实验：**

| 实验 | 格式 | bpw |
|---|---|---|
| Kimi-K2.5 / Llama-3.1-Instruct | **GSQ 自有的对称 group-wise 标量格式** | **2.13 bpp** |
| Qwen3-8B GGUF K-Quant | **标准 GGUF Q2_K**（in-format refine） | **2.625 bpw**（Q2_K 自身的 bpw） |

### E1.3 ⇒ 更正与影响面

**R4 `shortlist.md` §2.1 原文**：
> "**产物** | **GGUF K-Quant（2.13 bpp，位级兼容标准 `Q2_K`）**，*"runs unchanged on llama.cpp / Ollama / LM Studio"*"

**更正为**：

> **产物** | **两条路径，bpw 不同，不可混用**：
> ① **GSQ 自有对称 group-wise 标量格式**：**2.13 bpp**（Kimi-K2.5 / Llama-3.1-Instruct 实验）。
> ② **GSQ 对现成 GGUF K-Quant 的 in-format refine**（Qwen3-8B，Q2_K）：**位级兼容标准 Q2_K，因此 bpw = 2.625**，avg score 50.03 → 56.28；产物在 llama.cpp / Ollama 上原样跑。
> ⇒ **⇒ "GSQ → 现成 Q2_K" 是合理部署方向，但这条路径的实际 bpw 是 2.625，不能用 2.13 计算其容量优势。**

**容量账的重算** `[推算]`（27B 参数）：

| 方案 | bpw | 27B 权重字节 | 相对 Q4_K (4.5) |
|---|---|---|---|
| Q4_K | 4.5 | **15.19 GB** | 1.00× |
| **Q2_K（标准 GGUF）** | **2.625** | **8.86 GB** | **1.71×** |
| GSQ 自有格式 | 2.13 | 7.19 GB | 2.11× |
| IQ2_XS | 2.3125 | 8.03 GB | 1.95× |
| Mirai S（混合三布局） | 2.433 | 8.45 GB | 1.85× |

**⇒ 三个必须改的推论**：

1. **"2-bit 路线"的字节优势普遍小于此前假设**：Q2_K 相对 Q4_K 只有 **1.71×**（不是 4.5/2.13 = 2.11×）。
2. **★ Q2_K 比 IQ2_XS 更宽**（2.625 > 2.3125）⇒ **若目标是纯省字节，llama.cpp 上更优的 2-bit 选择是 IQ2_XS，不是 Q2_K。** Q2_K 的优势在别处（它是 llama.cpp/MLX 现成内核 + GSQ 可在格式内提升分配质量）。
3. **⇒ 候选二的定位要改**：**GSQ 的价值是"同一格式内的质量提升"，不是"更少的字节"。** 它对 Q2_K 的作用是**把同一 2.625 bpw 下的分数从 50.03 抬到 56.28**。

**向后传播**：`2026-10-r2-report.md` §2.2 与 §8.1 的 "GGUF K-Quant 产物（2.13 bpp，位级兼容标准 Q2_K）" **同属此错**。按 Issue #1 的契约，R2 原报告**不修改**，在此登记。

## E2 【P0 · 推导错误】配对检出力表的单调性反了

### E2.1 原表（`quality-gates.md` §B.5(c)）与错在哪

原表给出：n = 250 时，ψ = 0.10 / 0.15 / 0.20 对应 MDE = **6.2 / 4.6 / 3.7 pp**。
⇒ **ψ 越大反而 MDE 越小 —— 方向反了。**

### E2.2 正确的推导

配对二元设计下，记 ψ = **不一致率**（discordant rate），δ = 两种方法的准确率之差：

```
Var(Ȳ_A − Ȳ_B) = ψ − δ²        ⇒  SE ≈ sqrt(ψ / n)
```

McNemar 统计量近似 `z ≈ δ·sqrt(n/ψ)`。要达到检验水平 α（双侧）与功效 1−β：

```
MDE = δ_min = (z_{1−α/2} + z_{power}) · sqrt(ψ / n)
```

⇒ **ψ 越大 ⇒ 噪声越大 ⇒ 同一 n 下所需 MDE 越大。**（原表把这一关系写反。）

### E2.3 重算表（α = 0.05 双侧，power = 0.8 ⇒ 系数 z_0.975 + z_0.8 = 1.960 + 0.842 = **2.802**）`[推算]`

| n \ ψ | 0.10 | 0.15 | 0.20 |
|---|---|---|---|
| **100** | **8.9 pp** | **10.8 pp** | **12.5 pp** |
| **250** | **5.6 pp** | **6.9 pp** | **7.9 pp** |
| **500** | **4.0 pp** | **4.9 pp** | **5.6 pp** |
| **1000** | **2.8 pp** | **3.4 pp** | **4.0 pp** |
| **2500** | **1.8 pp** | **2.2 pp** | **2.5 pp** |

**⇒ 对阈值制定的三条直接后果**：

1. **"下降 ≤ 2 分"需要 n ≈ 2500（ψ = 0.10）到 n ≈ 5000+（ψ = 0.20）**，而不是我原表暗示的"n ≥ 1000 即可"。
2. **在 n = 250 的子集上只能检出 5.6–7.9 pp 的退化** ⇒ **"≤2 分"这条门槛在 250 题上完全无信息量**（这与我在 §B.5 的结论方向一致，但量级与理由当时是错的）。
3. **⇒ 门槛必须与 (n, ψ) 一起写死**；若样本量受限，**判据应改为"是否超出噪声底"（相对判据），而不是绝对分数**。

**⚠ 口径限制（按审查意见补）**：上表是**正态近似**，未含 McNemar 条件检验的离散性、连续性校正与 δ 对 ψ 的耦合（δ/ψ 决定 discordant 对的方向偏斜）。**最终阈值必须用配对 exact-power 或 simulation 重算**，不得直接用本表定案。

## E3 【P0 · 判据方向错误】CI 上下界写反

### E3.1 原表述（`quality-gates.md` §B.6）

> "**文档级配对 bootstrap 的 95 % CI 下界 ≤ 1.10×**"

### E3.2 问题

若统计量是**比值** `R = PPL_quant / PPL_base`，要证明"退化不超过 10 %"，需要的是 **R 的单侧上置信界 ≤ 1.10**。
**下界 ≤ 1.10 在估计很差或不确定性很大时也会"通过"**（例如点估计 3.0、下界 0.8 ⇒ 0.8 ≤ 1.10 ⇒ 通过）⇒ **这条判据几乎恒真，是无效门禁。**

### E3.3 更正

> **判据改为（等价的三种写法，任选其一并写死）**：
> ① **单侧 95 % 上置信界** `U95(R) ≤ 1.10`（R = 量化/基线 的 PPL 比值）；或
> ② **非劣性检验**：在 `H0: R ≥ 1.10` 下用配对 bootstrap 得到单侧 p，**要求 p < 0.05**；或
> ③ 在**配对 ΔNLL**（差值而非比值）上做同样的单侧上界：`U95(ΔNLL/ NLL_base) ≤ +10 %`。
>
> **并明确计算单位**：
> - **bootstrap 的重采样单位 = 文档**（不是 token、不是句子）；每次重采样后**重新计算整条统计量**（先逐文档求 NLL，再聚合），再取分位数。
> - 配对结构在重采样时**按文档对一起重采样**（量化与基线共用同一批文档），保持配对。
> - 报告 **n_documents**、**重采样次数 B**（建议 ≥ 10⁴）、**百分位法还是 BCa**。
>
> **⇒ 这是比原来的"下界"更严的判据**（单侧 + 上界），应按此执行。

## E4 【P1 · 探针设计错误】S0.1 的"逐位相同"门不适用于 OSAQ

### E4.1 原表述（`quality-gates.md` §B.4 Stage 0）

> "**S0.1** | **精确等价性** | 对"数学等价"变换（OSAQ 式离线加性折叠、把旋转变换折叠进权重），在固定 prompt 集上比较**反量化后的权重**与**logits** | **反量化权重应逐位相同**；logits 的差异应 ≤ bf16 舍入 |"

### E4.2 问题

**OSAQ 改变权重本身** ⇒ "变换前后的 W 逐位相同"这个门**按构造就会失败**，它测的是一个不成立的东西。
另外 **BF16 舍入本身不保证 bitwise 精确** ⇒ 即使是可折叠的旋转，"逐位相同"也过严。

### E4.3 更正：拆成两个不同的探针

> **S0.1a —— 变换实现一致性（离线折叠 vs 在线展开）**
> - **对象**：同一变换 T 的**两种实现**——(i) 离线折叠（`W' = T(W)` 存盘、运行时不做任何变换）与 (ii) 在线展开参考实现（运行时施加 T）。
> - **比较对象**：**函数输出**（logits / 层输出），**不是权重**。
> - **判据**：**数值容差**，例如 `max |Δlogit| ≤ c · ulp(bf16)`，或逐层输出的相对误差 ≤ 预先声明的容差。**不要求 bitwise。**
> - **意义**：它回答的是"**离线折叠与在线展开等价吗**"——这才是"变换能否安全折叠、折叠后是否与不折叠同解"的正确表述。
>
> **S0.1b —— 折叠的幂等/正确性（只对声称"数学等价"的变换）**
> - 对 PeRQ 式"把变换合并进相邻层权重"的方案，检验**复合后的线性映射**在目标精度下相等（仍测**输出**，不测权重比特）。
> - 若某变换声称 L0（精确算术等价）⇒ 才有资格要求 bitwise；否则一律用容差。
>
> **⇒ 删掉"反量化权重应逐位相同"这一句。** 它对 OSAQ 是错的，对 BF16 也过严。

## E5 【P1 · 推论越界】三条证据边界需要收回或收紧

### E5.1 "23×" 不是有效的横向性能比较 ⇒ 不能用于给 Trellis 退出排位

**原表述**（`shortlist.md` §3.1、§4）：用 "Mirai S 在 base M4 上 4 tok/s" 对 "GSQ Q2_0 模型卡 93.79 decode t/s"，得出 "**同位宽差约 23×**"，并把它作为**排除 trellis 候选的理由之一**。

**问题**：两个数字的 **模型、芯片型号、软件栈、测量协议、是否含投机解码** 全部不同 ⇒ **不是横向比较。**

**更正**：
> **撤回"23×"作为一个可用于排位的比值。** 正确表述：
> "**已公布的两个 2-bit 实现各自报告了各自的数字：Mirai S 在 base M4 上 ≈4 tok/s（模型卡）；GSQ-RCO Q2_0 报告 93.79 decode t/s（模型卡，硬件口径未核）。二者条件不同，不能相减或相除。**"
>
> **⇒ 因此，排除 trellis 的理由必须改为以下几条与性能数字无关的证据**：
> 1. **质量从未被公开测量**（公开产物只有解码器数值一致性与字节账）；
> 2. **编码器不公开**（第三方能消费、不能生产）；
> 3. **公开的模型是 QAT 产物**（见 E5.2）；
> 4. **上游三个 PR 全部未合并**，其中 uzu #900 的 diff **在 macOS CI 上编译不过**（WorkBuddy R4 的本机日志）；
> 5. **已发布二进制里那条 M1–M4 路径的来源分支未公开**。
>
> **⇒ "有内核但慢"应改为"**有内核，但公开证据里既没有质量、也没有可比的性能**"。**

### E5.2 Mirai S 的 QAT 产物不能当作"冻结权重 PTQ"的证据

> **更正**：Mirai S 的 2-bit checkpoint 由 **QAT** 产出（candidate 含 "+ QAT 38zmrr2"；dense 参照包为 `q38zmrr2-package-qat-v1`）⇒
> **它能证明的**是"**这种格式 + 这套内核可以产出一个可发布的模型**"；
> **它不能证明的**是"**冻结权重 PTQ 能达到同样的质量**"。
> ⇒ 任何以 Mirai S 为依据的质量/可行性推断，都必须带上"**这是 QAT 结果**"的限定。

### E5.3 OSAQ 在同码率上**没有直接速度收益** ⇒ 与加速目标的关系只能经"使更低位宽达标"这一环

**原表述**（`shortlist.md` §1.4）已说"它不产生任何加速"，但**没有说清它与本项目总体目标的关系**。

**更正并据此重构候选一**：

> **候选一应当被表述为"让 2-bit 达标"，而不是"在 4-bit 上更好"**：
> - **在 4-bit 上，OSAQ 与本项目的加速目标完全无关**（字节、FLOPs、串行轮次都不变）。
> - **它唯一可能对本项目有意义的路径是：让某个更低位宽变得可用。**
> ⇒ **⇒ 候选一的评估点必须移到最低候选位宽上**（例如 2-bit 的直接可算码：MLX affine g64 2-bit = **2.5 bpw**、标准 Q2_K = **2.625 bpw**），而不是在 4-bit 上做 A/B。
> ⇒ **⇒ 并且这条链必须被显式验证**：*若 OSAQ 不能让 2-bit 达标，则它对本项目的价值为零*（即使它在 4-bit 上确实提升质量）。
> - **Kill condition 相应修订**：**在 2-bit 直接可算码上，S0.3 显示离群点最严重的那些层的相对误差没有下降 ⇒ 变换没起作用 ⇒ 候选一在本项目上作废。**
> - **补充 Kill condition**：若在 2-bit 上误差下降，但下游能力仍不达标（超出噪声底）⇒ **候选一不改变本项目的结论**（它只是把"2-bit 不达标"换成"2-bit 差一点仍不达标"）。

## E6 【P1 · 缺口】免费云方案：可执行矩阵（规划级，不执行、不开实例）

**授权状态**：本 Issue 仅授权研究、阅读、方案设计。**本文件不执行任何实验、不编译、不下载、不开任何云实例。** 下表是**执行前需要先解决的条件清单**，不是执行计划。

### E6.1 容量算术（先算，再谈云）

`[推算]`，以参数数 × bpw/8 计，**不含**运行时、激活、CUDA context、KV cache：

| 模型 / 位宽 | 权重字节 | 27B 类 (27.78 B) | 8B 类 (8.03 B) |
|---|---|---|---|
| BF16 (16 bit) | ×2 | **55.6 GB** | **16.1 GB** |
| Q4_K (4.5 bit) | ×0.5625 | 15.6 GB | 4.5 GB |
| Q2_K (2.625 bit) | ×0.328125 | **9.1 GB** | 2.6 GB |
| GSQ 自有 (2.13 bit) | ×0.26625 | 7.4 GB | 2.1 GB |
| IQ2_XS (2.3125 bit) | ×0.289063 | 8.0 GB | 2.3 GB |

**⇒ 关键结论**：
- **8B BF16 = 16.1 GB 权重 + 运行时/激活/KV ⇒ 超过单张 16 GB（Kaggle T4）的可用显存** ⇒ **8B BF16 不能在单卡 T4 上跑**（除非显式 CPU offload，且必须标注为非同条件）。
- **27B BF16 = 55.6 GB 权重 + 缓冲 ⇒ 需 ≥ 80 GB 显存（单张 A100/H100 80 GB）或分卡**。
- **27B @ 2.625 bpw = 9.1 GB ⇒ 单张 16 GB 卡装得下**，且给 KV cache 留出 ~4–5 GB（≈20–30k token 上下文量级）⇒ **这正是"免费云能做什么"的分界线**。

### E6.2 矩阵（条件必须逐格核对，**均为执行时的动态外部条件**）

### E6.3 ⇒ 结论与执行前置条件

1. **Stage 0 / Stage 1（0.6B 机制与能力形状）不需要云** ⇒ 可以在本地做，**但仍需单独的执行授权**（本轮未授权任何运行）。
2. **Stage 2（真正的门槛，≥ 8B 真实模型）必须落在有 CUDA 的环境**：
   - **8B @ 4-bit 与 27B @ 2.625 bpw** ⇒ 免费层（Kaggle 双 T4）**在算术上装得下**，**但配额、会话长度、无持久盘、是否给到第二张卡都是动态条件**；
   - **8B BF16 与 27B BF16** ⇒ 免费层**装不下** ⇒ 只能走付费（Modal/RunPod）或分卡 ⇒ **必须明确标注为非同条件**。
3. **⇒ 一条给执行者的硬性前置**：**在任何平台开实例之前，必须先核对当日的 (a) 配额与计费规则、(b) 实际分配到的 GPU 型号与显存、(c) 会话时长上限、(d) 磁盘持久性**，并把这四项写进实验记录；**缺一项则该次运行的数据不得与本仓库的其它数字并列比较**。
4. **⇒ 本轮不执行、不开实例。** 上表是**条件清单**，不是行动授权。
