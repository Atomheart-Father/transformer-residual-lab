# Stage 2.0 报告：冻结权重的稀疏依赖 DAG（Block 10–17 及全模型）

**模型**：`mlx-community/Qwen3-0.6B-Base-bf16`（28 层，hidden 1024，16Q/8KV，vocab 151936，tied embedding），BF16，权重全程冻结、零训练。
**硬件**：Apple M4 Pro / 24 GB，MLX 0.31.2 / mlx-lm 0.31.3。
**语义**：`x_i = h_0 + Σ_{j∈P_i} Δ_j`，`Δ_i = F_i(x_i) − x_i`，`h_final = h_0 + Σ_i Δ_i`。只改依赖与时序，28 个 Block 全执行、全部权重不动。深度 = 真实最长依赖链（level 数），不是分组数。
**数据**：全新划分 s20_cal（64 窗测量）/ s20_val（32 窗选型）/ s20_test（64 窗盲测，只跑一次）/ s20_ood_c4（64 窗 C4 en validation），与既有 11 个 split 两两断言 105 对零重叠。

---

## 1. 结论

**对「固定分组是否浪费并行机会 / 稀疏 DAG 能否在同等深度打赢固定分组」：未支持。**

预发表的选择规则（`results/stage2_0/selection.json`，盲测开启前冻结）与三轮结果一致：

1. **质量几乎只由关键路径深度决定，同深度下没有任何稀疏、非连续或移位 DAG 打赢固定连续分组。** 深度 28/27/26/25/24/23/22 对应盲测 ΔNLL 0.0000 / 0.0309 / 0.0749 / 0.1240 / 0.1838 / 0.3406 / 0.5499（PPL 比 1.000/1.031/1.078/1.132/1.202/1.406/1.733）。同深度 24 的选型集比较（s20_val）：g2（连续配对）0.1931 < 非连续同层数 noncontig 0.2119 < 混合层大小 mix4 0.2658；同深度 25 上 p3 与 hyp-shift 的差距（cal 0.1302 vs 0.1354）小于深度本身造成的效应，CI 重叠。深度 27 上配对位置无差异（前/中/后 = 0.0316/0.0296/0.0330，cal）。
2. **被放弃的上游更新是「位置加权」的，不是计数的。** 等深度（24）、等漏更新（4）的 8 宽窗口只差位置：Block 0–7 配对花 7.57 nats，5–12 花 0.37，10–17 花 0.19，15–22 花 0.22，20–27 花 0.71。最贵与最便宜的位置相差 40 倍。全模型上 irr-a（80 个漏更新）比均匀 g4（42 个）在同等深度 7 好 3.3 倍，因为 irr-a 把大组放在中段、把首 3 层与末组保护起来。
3. **删层轴全面落败**：每个匹配深度上删层都比同深度全 block DAG 差 3.4–4.4 倍（深度 27：删 1 层 0.1061 vs 全 28 block 的 pair-mid 0.0309）。DAG 轴与删层轴必须分开报告。
4. **理论深度在两个延迟场景都没有兑现**：257 token prefill 下深度 28→7 无收益（merge 记账反付 6–21%）；1 token + KV cache 的 decode 下深度 28→14 同样无收益（lazy 6.14→6.34 ms，eager 反而慢 21%）。真实结论是 roadmap 门槛 3 的那一档：**依赖深度可缩短，单 GPU 性能暂未兑现**，不是推理提速。

## 2. 设置与门槛 0（正确性）

执行器 `scripts/dag_exec.py` 支持两种 merge 模式：`materialized`（合并点物化 bf16 + 串行延续捷径，对链/分组/窗口结构逐位复现生产实现）与 `roadmap`（每个输入都是 `h0 + Σ_{P_i} Δ_j` 单一 fp32 累加，对任意前驱集忠诚）。

门槛 0 六项检查全过（ fidelity 修复后重跑，`results/stage2_0/equivalence/`）：

| 检查 | 内容 | 结果 |
|---|---|---|
| G0.1a | 全前驱图退化为串行链 vs 原模型 | ΔNLL = 0、top1 = 1、max_abs = 0（逐位） |
| G0.1b | 去掉串行捷径，只剩 merge 机制 | rel ≤ 0.0159、\|ΔNLL\| ≤ 0.0057 |
| G0.2a | g2 依赖 DAG vs 生产 g2 实现 | max_abs = 0（逐位） |
| G0.2b | 生产参考 vs `run_plan` | max_abs = 0 |
| G0.2c | prefix-k g2 vs Stage 1.5 历史数字 | 56 个对比点差 0.00e+00 |
| G0.2d | 窗口 DAG vs `run_plan(window-mid-g2)` | max_abs = 0 |

**忠实性修复（本阶段的关键 bug）**：串行延续捷径最初只要求「新增前驱 = {i−1}」，当一个前驱集丢掉中间边、保留后边时会错误复用运行状态，使探针退化为 no-op（`drop1_b12_m10` 曾显示 0.0000）。修复为要求 `P_i == {0..i−1}`（完整前缀）后才允许读 `out_{i−1}`，否则必须走 merge/稀疏回退分支。修复后 materialized 模式对任意前驱集忠诚，两种模式的探针数值一致（0.0326 vs 0.0326），门槛 0 指标不变。代数与 merge 语义测试 34 项（`tests/test_dag_semantics.py`）全过。

## 3. 实验 B：每条上游边都重要（局部干预探针）

77 个探针 × 12 个校准样本 × 2 种 merge 模式，构造噪声 floor rel 0.0019（`results/stage2_0/probe/`）：

1. **单边删除**在窗口出口处即有 0.0197–0.0433 rel_rms（噪声 floor 的 10–20 倍），被真实后缀 Block 18–27 放大 2.2–3.2 倍。没有可免费删除的边。
2. **每块最新的前驱通常最贵**（8 块中 7 块成立）：b17 的 m16 = 0.0433 是全窗最贵的单边，b13 的最贵却是 m11 = 0.0352。边的重要性必须逐块测，不能由位置推断。
3. **组合删除近似线性相加、无突变**：2/4/6/8 条边分别 0.0497 / 0.0784 / 0.0858 / 0.1028。既不存在「单独没问题、组合突然崩」的边集，也不存在便宜的成组删除。
4. **老更新集体重要**：只保留最近 k 条更新（k=1/2/4）代价 0.167 / 0.137 / 0.102，比丢掉最新一条的任何单边删除更差。
5. 探针的排序能力在自由运行中被验证：深度 27 的配对位置，探针单边代价 0.0300（pair-mid）< 0.0377（pair-first）< 0.0433（pair-last），与盲测 ΔNLL 0.0309 < 0.0433 < 0.0543 同序。**探针能排序，不能定阈值。**

## 4. 实验 C：自由运行筛选、选型与一次性盲测

候选 16 张 DAG × 2 种 merge 模式 + 4 个删层对照，窗口固定 Block 10–17。

**s20_cal 筛选（12 样本）→ s20_val 选型（32 样本，规则先定）→ 盲测（64+64 样本，只跑一次）**：

| 候选 | 深度 | 漏更新 | val ΔNLL | test ΔNLL | test PPL 比 | ood ΔNLL | ood PPL 比 |
|---|---|---|---|---|---|---|---|
| serial | 28 | 0 | 0.0000 | 0.0000 | 1.000 | 0.0000 | 1.000 |
| pair-mid | 27 | 1 | 0.0300 | 0.0309 | 1.031 | 0.0249 | 1.025 |
| p2 | 26 | 2 | 0.0774 | 0.0749 | 1.078 | 0.0691 | 1.072 |
| p3 | 25 | 3 | 0.1273 | 0.1240 | 1.132 | 0.1072 | 1.113 |
| g2 | 24 | 4 | 0.1931 | 0.1838 | 1.202 | 0.1506 | 1.163 |
| mix3 | 23 | 7 | 0.3555 | 0.3406 | 1.406 | 0.2840 | 1.328 |
| g4 | 22 | 12 | 0.5731 | 0.5499 | 1.733 | 0.4708 | 1.601 |
| del-w1（删层） | 27 | — | 0.1001 | 0.1061 | 1.112 | 0.1102 | 1.117 |

同深度竞争（cal，12 样本）：深度 24 上 g2 0.1874 < 非连续同层数 noncontig 0.2161 < mix4（[3,2,2,1]）0.2582；深度 25 上 p3 0.1302 ≈ hyp-shift 0.1354（CI 重叠，单样本上的 4 倍差异是噪声）；深度 27 上配对位置前三中后 0.0296/0.0316/0.0330 无差异。稀疏多前驱图 sparse-x1（80 个漏更新）彻底失败（5.04 nats，top-1 跌到 0.08）。

结论：**在 10–17 窗口内，固定连续分组已经位于深度—质量帕累托前沿上**；层级大小的 multiset 是唯一自由度，而连续均匀配对在任意深度都是漏更新最少的。OOD（C4）排序完全一致且惩罚略小，说明该结论不是 wikitext 的特有现象。

## 5. 全模型与位置：为什么会这样

`results/stage2_0/full/screen.json`（s20_cal，12 样本）：

1. **位置依赖（等深度 24、等漏更新 4，只差位置）**：Block 0–7 → 7.5721；5–12 → 0.3677；10–17 → 0.1874；15–22 → 0.2243；20–27 → 0.7145。中段有一个清晰的内部最小值，向两端急升。这与 Stage 1 的「误差在 layer 0–4 一次性产生」互相印证：早层并行破坏的是后续所有层依赖的基座，晚层并行破坏的是输出端的最后整理。
2. **全模型深度—质量曲线**：serial 0.0000（深度 28）/ prefix3-g2 1.0568（16）/ g2 8.4074（14）/ irr-a 3.8027（7）/ irr-a-t3 5.7347（7）/ g4 12.4477（7）/ keep7 13.9310（7）/ keep9 14.4005（9）。深度不再是唯一变量：prefix3-g2 比 g2 深 2 级却好 8 倍，irr-a 比 g4 漏更新多近一倍却在同深度好 3.3 倍。
3. **统一机制**：漏更新的代价由位置加权。irr-a 的大组（8 层、9 层）压在中段 3–25，恰好落在位置曲线最便宜的区域；首 3 层串行 + 末组 2 层保护了两端最贵的区域。均匀 g4 把大组平铺到 0–3 与 24–27，代价自然最高。
4. **删层轴在最深的比较点上也是最差的**：keep7（13.93）> g4（12.45）在深度 7 同台；irr-a（3.80）大幅赢过两者。

## 6. 问题三：理论并行能否在 M4 Pro 兑现（两个场景都测了）

**Prefill（257 token，`results/stage2_0/bench/bench.json`）**：

| 模式 | 深度 | median | p90 | 峰值内存 | 相对串行-eager |
|---|---|---|---|---|---|
| serial-eager | 28 | 70.15 ms | 72.94 | 1231 MB | 1.000 |
| serial-lazy | 28 | 61.32 ms | 65.68 | 1672 MB | 1.144 |
| g2-eager | 14 | 83.90 ms | 85.51 | 1259 MB | 0.836 |
| g2-lazy | 14 | 74.25 ms | 77.04 | 1658 MB | 0.945 |
| g4-lazy | 7 | 65.11 ms | — | — | — |

理论深度 28→14→7 没有换来任何延迟收益，merge 记账反而多付 6–21%。机制：该规模下单 Block 的 matmul 已把 GPU 打到 ~3.4 TFLOP/s（约占峰值 20–30%），块间并发没有空余算力可抢；惰性图峰值内存还高 36%。

**Decode（1 token + KV cache，`results/stage2_0/decode/decode.json`）**：先做正确性检查——串行缓存解码 vs 全长无缓存前向，max_abs 差 4.0（bf16 kernel 舍入量级）、ΔNLL 差 0.0119（比 Stage 2.0 最小的结构效应小一个数量级以上），通过后才计时。共享串行 prefill 建好相同缓存，每变体单独计时：

| 变体 | 深度 | lazy median | eager median |
|---|---|---|---|
| serial | 28 | 6.141 ms | 10.778 ms |
| g2 | 14 | 6.338 ms | 13.079 ms |
| prefix3-g2 | 16 | 5.982 ms | 12.891 ms |
| win-g4（10–17） | 22 | 6.230 ms | 11.796 ms |
| win-g2（10–17） | 24 | 6.331 ms | 11.801 ms |

lazy 调度下深度减半没有任何收益（6.14→6.34 ms，最快的 prefix3-g2 只快 2.6%，在噪声内）；eager 调度下 DAG 反而慢 9–21%。原因：decode 步的耗时由 28 个 Block 的总 kernel 工作量与启动开销决定，DAG 不减少总工作量；而惰性图本来就会重叠独立 kernel，「依赖链」从来没有真正串行化过；merge 记账又增加了额外 kernel。**batch=1 之外未测**（batch>1 只会让每步更算力密集，预期差距更大，但这是推断不是实测）。

## 7. 负结果与失败案例（全部保留）

1. **bench 否定**：prefill 深度 28→7 零收益，merge 记账 6–21% 额外成本；惰性峰值内存 +36%。
2. **decode 否定**：lazy 深度 28→14 零收益；eager DAG 慢 9–21%。
3. **稀疏/非连续/移位 DAG 全部输给同深度固定分组**（窗口内 5 个家族、全模型 3 个家族，无一例外）。
4. **sparse-x1 多前驱图**：5.04 nats，top-1 0.08，接近随机。
5. **单样本假象**：hyp-shift 在 1 样本上显示比 p3 差 4 倍，12 样本后消失（CI 重叠）——小预算筛选必须做多样本才能定性。
6. **探针 no-op 假象**：串行延续捷径的忠实性 bug 曾让 `drop1_b12_m10` 显示 0.0000，即「这条边不重要」的假阴性；修复后为 0.0326。
7. **miss 计数不是普适预测器**：mix4（5 misses）比 noncontig（6 misses）差，irr-a（80）比 g4（42）好——必须位置加权。

## 8. 局限

- 只在 Qwen3-0.6B-Base（0.6B、28 层、GQA）上测；结论不能外推到其他规模/架构。
- 只测静态 DAG；依赖动态数据的自适应调度未测。
- decode 只测 batch=1；batch>1 与更长 KV cache 未测。
- 中窗 10–17 的窗口实验用 MLX 的默认调度；专用 kernel 融合/流水可能改变 launch 开销占比，但不会减少总计算量。
- 未做迭代修正（把前一轮的预测作为下一轮输入），这是 SNLP 类方法的核心，本阶段未触及。

## 9. 下一步最便宜的决定性实验

按「每单位算力能翻转哪个结论」排序：

1. **给 DAG 一次真正的推理侧机会：把窗口 DAG 的 4 个独立 Block 放进一个 batch（shape (4,1,dim) 的单次 matmul）**。当前实现是逐 block 调 layer，独立 kernel 之间靠惰性图重叠； batch 合并后 4 个 Block 的计算变成 1 个大 GEMM，能直接检验「decode 步的 6 ms 里有多少是启动开销、有多少是带宽」——这是本次否定结论最可能的翻转点，估计 <100 行改动。
2. **晚窗/早窗的补偿实验**：既然位置加权成立，最贵的两端（0–7 与 20–27）是否值得用 Stage 1.7 的单点补偿器买回？ Stage 1.8 已经证明 128 宽串行单元能传递必要信息，把它接在晚窗 DAG 的汇合点上是明确的下一步。
3. **位置曲线的机制解释**：对早/中/晚三类窗口分别测「漏更新引起的隐藏态变化方向 vs Block 权重的左奇异空间」的相关性，把 40 倍的位置差异归因到具体的谱结构上。

## 10. 不能宣称的结论

- 没有推理加速（prefill/decode 都无收益）。
- 没有质量可接受的深度压缩新方案（同深度最好也只是追平固定分组）。
- 没有把 0.6B 的结果推广到其他模型。
-  blind 数字只反映 wikitext 与 C4 两个语料的 257-token 窗口。
