# Stage 1.8 Teacher-Derived Serial Path

## 结论先行

1. 一个 128 宽、4 深的窄串行单元确实能够承担预训练 Transformer 在这一层的必要串行信息传递：
   它把 group [3..10] 这 8 层的净变化复现到 rel.err 0.61 / cosine 0.79，接入自由运行的并行主干后，
   同语料盲测 ΔNLL 从 4.0440 降到 3.5230。
2. 但"恢复部分 Oracle gap"不等于"接近原模型"。最佳变体仍停留在 ΔNLL 3.42–3.52（教师 3.4 倍困惑度），
   只取回 Oracle gap 的 24.8%–35.2%，Oracle gap 的 65%–75% 仍未回收。
3. 预训练参数继承在本轮有可测收益，但很小、而且分指标方向不一致（见第 6 节）。
4. f_a3z（完全不读并行主干输出）与读真实主干的 f_trunk 在统计上不可区分，且优于把两者都喂进去的
   f_a3。这说明该站点的修正信息并非来自并行组的输出。但这不等于已验证"绕过重型分支"（见第 5.3 节）。
5. 本轮没有宣称任何端到端加速。所有延迟都是串行实测。

## 1. 设置

模型：mlx-community/Qwen3-0.6B-Base-bf16，revision e8e73ff38f0eb570eb57ed044ef3f95588c43bc8，冻结，
不训练、不搜 DAG。

计算图：

```
Embedding -> Block 0 -> Block 1 -> Block 2 -> h3
                                            |- 重型路径：原始 Block 分组并行
                                            |- 轻型路径：Tiny 串行计算
                                                    残差融合 -> 输出
```

计划：irr-a:0|1|2|3-10|11-19|20-25|26-27（28 blocks / 逻辑深度 7）。
站点：SITE=3，即 group [3,4,5,6,7,8,9,10]，exit 状态索引 H11 = states[11]。
只替换这一处，其他组一律按原模型并行执行。

Tiny 规格：hidden 128、深度 4、1 个 q 头 / head_dim 128、intermediate 512。
block 直接复用 Qwen3 的 TransformerBlock 类，RoPE、RMSNorm、GQA、残差布局与教师一致，不做重新实现。

训练语料包含两种来源（wikitext-2 train + IMDB train），不再单一语料。

11 个 jsonl 划分已做逐窗口 sha256 断言，两两精确窗口重叠数为 0（data257/data_manifest.json 的

## 3. 参数提取（A3 的继承方法，与"仅教师监督训练"分开）

这是 SliceGPT 式迷你版，不是函数保持压缩：

- 对 h3 的协差矩阵做 PCA 正交旋转，取前 128 个坐标。top-128 能量占比 0.99975。
  注意第一特征值 176,473 远大于第二（5.14）——这是 Qwen3 的 massive activation 主导，
  "能量占比高"不等于"保留了任务信息"。
- 输入侧矩阵右乘 R，输出侧左乘 R^T；proj_in 取 R 的前 128 列，proj_out 取 R 的前 128 行的转置。
- 头选择按 LLM-Pruner 结构化准则（||q_head||*||o_head block||，数据无关），选 1 个 q 头及其
  GQA 配对的 kv 头：layer 3 -> q9/kv4，layer 5 -> q0/kv0，layer 7 -> q8/kv4，layer 9 -> q14/kv7。
- MLP 神经元按 ||W_gate||*||W_up||*||W_down[:,i]|| 取前 512 个。
- RMSNorm 权重重标定：factor 全部约等于 2.828（2.825–2.828），由实测 per-layer RMS 得到，不是拟合的。

结果：1,312,768 参数，3,147,776 FLOPs/token。继承 5 类权重，重新初始化 0 个。

必须写清楚的一点：1024 -> 128 丢掉了 87.5% 的残差坐标，16 个 q 头换成 1 个。
extract_manifest.json 的 not_faithful 字段原文如此。所以继承的是"经过旋转、切片、重标定后的
参数"，不是原函数；继承权重是否构成功能性初值必须实测，不能用"来自预训练"推断。

## 4. 实验 A：三种架构的串行蒸馏质量

目标（B1）：proj_out(h_out - h_in) 复现 (h_11^T - h_3)，即 group [3..10] 这 8 层的净变化。
用 delta 读出而不是直接读 h_out：教师 block 是"近乎抵消"的，直接读 h_out 会让窄模型先学会输出一个
巨大的再抵消的向量。这是本模块最关键的设计修正。

| 架构 | 参数来源 | 参数量 | FLOPs/token | 训练前 rel/cos | 训练后 rel/cos |
|---|---|---:|---:|---|
| A1 串行 MLP（无注意力） | 随机初始化 | 1,245,696 | 2,490,368 | 1.0066 / 0.0062 | 0.6154 / 0.7883 |
| A2 Tiny Transformer | 随机初始化 | 1,312,768 | 3,147,776 | 1.0495 / 0.0058 | 0.6117 / 0.7911 |
| A3 Tiny Transformer | 原模型参数继承 | 1,312,768 | 3,147,776 | 1.0096 / -0.0064 | 0.6141 / 0.7893 |

数字来自 fit_*.json（内部 val 划分）。三个变体结构相同（A2/A3 完全同结构同参数量）、预算相同、
seed 相同（20261019）。

盲测复核（fit_stats.json，cl_test 逐窗口）：

| 架构 | rel_err | cosine | pred_rms | target_rms |
|---|---:|---:|---:|---:|
| A1 串行 MLP | 0.6107 | 0.7918 | 0.7945 | 0.9910 |
| A2 Tiny Transformer | 0.6050 | 0.7961 | 0.7937 | 0.9910 |
| A3 Tiny Transformer | 0.6077 | 0.7940 | 0.7841 | 0.9910 |

量级参照：h3 的 RMS 约 13.44，8 层净变化的 RMS 只有 0.9910，并行组与教师 exit 的差 RMS 1.0911。
也就是说这一组做的事只有残差流尺度的 7% 量级。

### 4.1 注意力没有带来可测收益

蒸馏目标上，A2（有注意力，1.31M 参数 / 3.15M FLOPs）比 A1（纯 MLP，1.25M / 2.49M）好 0.0057 rel.err。
逐窗口配对 bootstrap：d = +0.0057，CI [+0.0048, +0.0066]，frac+ 0.95，显著但幅度极小——
A2 用 26% 的额外 FLOPs 换来 0.9% 的相对 rel.err 改善。

但接入后方向反了。A1 与 A2 的最终 ΔNLL 对比（d = nll(A) - nll(B)，d < 0 表示 A1 更好）：

| 对比 | cl_val | cl_test | cl_ood |
|---|---|---|---|
| A1 (f_a1) vs A2 (f_a2) | -0.0487 CI[-0.0640,-0.0339] 显著 | -0.0341 CI[-0.0503,-0.0184] 显著 | -0.0406 CI[-0.0563,-0.0245] 显著 |
| A1 vs A2（原始 tiny 替换） | +0.0090 CI[-0.0141,+0.0347] 不显著 | +0.0212 CI[-0.0050,+0.0514] 不显著 | -0.0046 CI[-0.0253,+0.0160] 不显著 |

也就是说：走融合头时 A1 反而更好（三个 split 一致显著），直接把 tiny 输出当修正时两者不可区分。
而 A1 与 A3（同为 1,312,768 参数，但权重继承）在 ΔNLL 上不可区分（CI 见 6.3 节）。

把两个指标放在一起，正确的说法是：在这个尺度上，注意力没有给出方向一致的优势。
蒸馏目标上它略好（+0.0057 rel.err，代价是 26% FLOPs），最终 ΔNLL 上它略差（-0.034 至 -0.049 nats）。
两个方向的幅度都在"真实但很小"的区间，不足以支持"这个尺度必须保留注意力"，
也不足以支持"注意力有害"。

## 5. 实验 B：接入并行主干

### 5.1 融合头的构造

B2 要求 hat_h_11 = h_11^P + c，其中 c = H_phi(z_11, h_3, h_11^P)。五种 head 按模式区分输入：

| head | 模式 | 输入特征 | 参数量 | 训练 rel | val rel |
|---|---|---|---:|---:|---:|
| f_trunk | trunk | [a, p] | 787,712 | 0.7595 | 0.7639 |
| f_a3z | zero_trunk | [a, a, z] | 1,049,856 | 0.7477 | 0.7553 |
| f_a1 | tiny | [a, p, z_A1] | 1,049,856 | 0.7619 | 0.7703 |
| f_a3 | tiny | [a, p, z_A3] | 1,049,856 | 0.7654 | 0.7723 |
| f_a2 | tiny | [a, p, z_A2] | 1,049,856 | 0.7695 | 0.7766 |

a = h3（组入口），p = h11P（并行组真实输出），z = tiny(a)。目标都是 (h11T - h11P)。
训练内部 576/64 划分，30 epoch，lr 1e-3，batch 8。

注意 f_trunk / f_a3z / f_a3 三者的 z 都来自同一个 A3，所以它们之间的差别只来自"输入里有没有 p"。

### 5.3 f_a3z 为什么不读 p 仍然有效，以及这是否意味着绕过重型分支

先说现象。f_a3z 的输入是 [a, a, z]，p 那一半被换成第二个 a，head 完全看不到并行组的输出。
它的表现是 3.4220 / 3.5230 / 3.1055；读真实 p 的 f_trunk 是 3.4503 / 3.5413 / 3.1018；
两个都读的 f_a3 是 3.4690 / 3.5774 / 3.1361。逐样本配对 bootstrap（d = nll(A) - nll(B)，
d > 0 表示 B 更好）：

| 对比 | cl_val | cl_test | cl_ood |
|---|---|---|---|
| tiny-only (f_a3z) vs trunk-only (f_trunk) | +0.0283 CI[+0.0064,+0.0507] 显著 | +0.0183 CI[-0.0024,+0.0384] 不显著 | -0.0038 CI[-0.0226,+0.0156] 不显著 |
| trunk+tiny (f_a3) vs trunk-only (f_trunk) | -0.0187 CI[-0.0350,-0.0025] 显著 | -0.0361 CI[-0.0526,-0.0203] 显著 | -0.0343 CI[-0.0505,-0.0170] 显著 |
| trunk-zero+tiny (f_a3z) vs trunk+tiny (f_a3) | +0.0470 CI[+0.0238,+0.0709] 显著 | +0.0544 CI[+0.0330,+0.0770] 显著 | +0.0305 CI[+0.0141,+0.0468] 显著 |

f_a3z 对 f_trunk：三个 split 上两个显著区间不含 0 的方向相反（val 上 tiny-only 略好，test/ood 上
几乎无差），稳妥结论是"不可区分"。f_a3z 对 f_a3：三个 split 全部显著且方向一致，frac+ 0.69/0.72/0.78，
即 7 成左右样本上 tiny-only 更好。f_a3 对 f_trunk：三个 split 全部显著为负，加上 z 反而更差。

原因可以从三个已测量的事实直接推出，不需要额外假设：

第一，这一组的净贡献本来就小。h3 的 RMS 约 13.44，而 group 的净变化 (h11T - h3) RMS 只有 0.9910，
并行组与教师 exit 的差 RMS 1.0911。两者都只有残流尺度的 7%–8%。入口状态 a 的"信息量"在这种情况下
天然压过分支输出 p 的边际信息，所以把 p 换成 a 几乎不掉点。

第二，z 本身就是这个问题的答案。z = tiny(a) 的训练目标恰好是 (h11T - h3)，也就是 head 需要产生
的那个量。于是 head 的任务退化成"逐 token 校准 z 的幅度和方向"，而不是从 p 里推断什么。
这解释了为什么 f_a3z (3.4220) 明显好于 tiny_sub_a3 (3.4995)：head 确实加了校准，
但校准的对象是 z，不需要 p 参与。

第三，两组特征是冗余而非互补。证据就是上面第二、三行：同时喂 p 和 z 比只喂 p 差（f_a3 < f_trunk），
也只喂 z 也比只喂 p 好或持平（f_a3z >= f_trunk）。如果 p 与 z 提供互补信息，两者共用应该至少不差于
任一单独使用；实际相反。冗余的典型表现正是"加一个没用，还可能挤占容量"（f_a3 与 f_a1/f_a2 都是
1,049,856 参数，与 f_a3z 相同，容量没有被稀释，掉的点只能归因于特征冗余）。

那么这是否意味着重型分支被绕过了？不能这样写，理由有二。

其一，本实验没有删掉重型分支，只是让修正不读它。eval 的 run() 里
par = run_group(model, h, group, mask, mx) 是无条件执行的，f_a3z 只是不用 par 算 c。
所以"并行组输出对修正无贡献"这个结论，对应的是"计算了但忽略"，不是"可以不计算"。
真正的绕过测试需要跳过这一组、让下一个组直接消费 h3，那是 Stage 1.6 的删除实验，
那边已知删 8 层的代价很高、必须靠补偿才能拉回。

其二，即使将来做了删除实验，也不能自动宣称加速。删除后关键路径深度变化、访存变化、批处理变化
都会进实测，本阶段测得的 0.532–0.901 ms 只是单元独立前向的串行成本，不是端到端收益。
eval_summary.json 的 warning 字段每轮都写着"Sequential execution. No end-to-end speedup is claimed."

## 6. 本轮最关键的判定：预训练知识是否真的有帮助

结论要分三个指标说，因为它们方向不一致，混在一起说会得出错误结论。

### 6.1 短预算收敛（3 epoch）

| 探针 | 参数来源 | ep3 val rel | ep3 val cos |
|---|---|---:|---:|
| a1_short | 随机初始化 | 0.6624 | 0.7492 |
| a3_short | a3_init.npz | 0.6720 | 0.7406 |
| a2_short | 随机初始化 | 0.6913 | 0.7226 |

A3 对 A2：d = -0.0193，CI [-0.0201, -0.0184]，frac+ = 0.00，即 64/64 个窗口上 A3 的 rel.err 都更小。
这是明确的继承收益：相同预算下继承版本收敛更快。A1 又比 A3 好 0.0104（同样 64/64 窗口同号），
说明 3 epoch 这个点上"结构简单"比"参数继承"更值钱。

### 6.2 满预算蒸馏精度（20 epoch）

A2 反超。

| 对比 | split | d | CI95 | frac+ | 显著 |
|---|---|---:|---|---|---|
| A3 vs A2（rel.err） | cl_val | +0.0022 | [+0.0016, +0.0029] | 0.83 | 是 |
| A3 vs A2（rel.err） | cl_test | +0.0027 | [+0.0020, +0.0035] | 0.84 | 是 |
| A1 vs A2（rel.err） | cl_val | +0.0046 | [+0.0036, +0.0056] | 0.89 | 是 |
| A1 vs A2（rel.err） | cl_test | +0.0057 | [+0.0048, +0.0066] | 0.95 | 是 |
| A3 vs A1（rel.err） | cl_val | -0.0023 | [-0.0033, -0.0014] | 0.22 | 是 |
| A3 vs A1（rel.err） | cl_test | -0.0029 | [-0.0040, -0.0019] | 0.22 | 是 |

d > 0 表示 B 更接近教师。所以满预算排序是 A2 < A3 < A1（rel.err 越小越好），随机初始化最好。
幅度只有 0.002–0.003（相对 0.6%），但 CI 不含 0、frac+ 方向一致，是真实的小差距。

因此继承带来的收敛优势是暂时的：到 20 epoch 时随机版本已经追上并反超。

### 6.3 接入后的语言模型质量（这才是最终判定）

与 6.2 方向相反。

| 对比 | cl_val | cl_test | cl_ood |
|---|---|---|---|
| inherited-tiny (f_a3) vs random-tiny (f_a2) | -0.0371 CI[-0.0503,-0.0239] 显著 | -0.0343 CI[-0.0495,-0.0203] 显著 | -0.0307 CI[-0.0449,-0.0165] 显著 |
| serial-MLP (f_a1) vs inherited-tiny (f_a3) | -0.0116 CI[-0.0267,+0.0036] 不显著 | +0.0002 CI[-0.0145,+0.0146] 不显著 | -0.0099 CI[-0.0232,+0.0042] 不显著 |

d = nll(f_a3) - nll(f_a2) < 0 表示继承版更好。三个 split 全部显著、方向一致，幅度约 0.031–0.037 nats，
frac+ 0.23–0.30（即 7 成左右样本上继承版更好）。所以到最终 ΔNLL 这一层，继承是有稳定收益的，
幅度约等于本方案自有效应的 6%–7%（0.035 / 0.52），占 Oracle gap 约 2.5%。

### 6.4 把三条放在一起怎么读

- 继承的收益是真的，不是训练噪声：三个独立指标里两个方向有利（短预算 rel.err、最终 ΔNLL），
  且 ΔNLL 上三个 split 一致显著。
- 但幅度小：最终 ΔNLL 上 0.03 nats，占本方案自有效应的 6%–7%，占 Oracle gap 约 2.5%。
- 继承没有"让串行路径变得可行"这个量级的作用。A2 随机版接入后 ΔNLL 3.5061/3.6118/3.1668，
  与 A3 的 3.4690/3.5774/3.1361 在同一档。
- 一个必须指出的现象：A3 的蒸馏 rel.err 比 A2 差 0.0027，但接入后 ΔNLL 比 A2 好 0.0343。
  两个指标方向相反。这符合 Stage 1.7 已确立的结论"状态 MSE 会高估/错判能力，能力只看
  ΔNLL/KL/top1"——教师状态相似度和实际语言模型质量不是同一个东西。

至于"是提取方法破坏了原有功能，还是结构本身不适合"：本轮证据不支持"破坏功能"这个解释。
如果提取把权重打乱了，A3 在训练前应当与随机初值不可区分，3 epoch 时也不该有 64/64 窗口一致的
优势。实际情况恰好相反：训练前 A3 的 pred_rms 0.1317、A2 的 0.3219、A1 的 0.1204，
继承版与串行版 MLP 的输出尺度天然接近教师 target 的 0.99 量级，随机版则偏离；
这说明继承来的统计结构仍在起作用。更合适的说法是：提取保留了真实但有限的功能性初值，
它加快早期收敛、略微改善最终接入质量，但不足以改变这个尺度的串行单元能达到的上限。

诚实修正一处：用户点名的表里第一行"原普通 MLP"在 Stage 1.8 的设定下对应 A1 串行 MLP

这个表有三处比较限制，必须一起说明，否则会把表读成"架构排序"而它并不是：

1. 行与行的 head 模式不同。A1 / A2 只有 trunk+tiny 一种融合头；A3 额外有 zero_trunk 头
   （f_a3z）。表里 A3 给的 3.5230 来自 f_a3z，A1 / A2 给的 3.5777 / 3.6118 来自各自的
   trunk+tiny 头。若只比 trunk+tiny 模式，三者在 cl_test 上是 3.5777 / 3.5774 / 3.6118，
   即 A1 与 A3 并列最好、A2 最差，而 A1 与 A3 的配对 CI 不含 0 的方向结论（不显著）。
   所以"哪个架构最好"在本轮没有定论，能定论的是 A2（随机版 Tiny）稳定垫底。
2. 教师状态误差列测的是"复现 8 层净变化"的能力，接入后 ΔNLL 列测的是"修正主干输出"的能力。
   两者不是同一件事：A2 的 rel.err 最好（0.6050）但 ΔNLL 最差（3.6118），A3 的 rel.err 居中
   （0.6077）而 ΔNLL 最好。这正是 Stage 1.7 已确立的"状态相似度不能代表能力"。
3. Stage 1.7 那一行只是量级参照。它的 3.3155 来自 test_v2——该 split 在本轮之前已被多次查看，
   不能当作盲测。本轮三行全部来自从未参与任何选择的 test_v3。两者不能直接比大小。

## 9. 停止节点与明确不做的事

本轮按指令停在局部 group 3–10 的三种架构对照与补偿效果评估，不做以下任何一件：

- 不做实验 C（扩展到 group 5）。A3 相对 A2 只在本方案自有效应的 6%–7% 量级，不构成扩展到 28 层的依据。
- 不扩大到更大 hidden / 更深 / 更多参数的 Tiny。本轮结论已足以描述这个尺度的行为。
- 不重新训练、重新采集或重新评估。本轮所有数字来自既有 table.json / fit_stats.json /
  paired_stats.json / eval_summary.json。
- 不宣称端到端加速，不把"恢复 34.7% Oracle gap"写成"接近原模型"。
